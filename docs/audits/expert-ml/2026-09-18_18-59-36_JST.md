# 2. P0 / P1 / P2 错误与风险定位

## EML-P0-LABEL-TIE：目标“严格 >”与 first-hit 路径使用“>=”不一致【确认错误】

**固定源码：** `5081139.../src/labels.py`，函数 `forward_outcomes()`。

当前最小逻辑：

```python
newly = (~hit) & valid & (high_d >= target)
path_low_to_hit[newly] = run_min[newly]
...
bull = (forward_high > target)
gate_low = np.where(np.isfinite(path_low_to_hit), path_low_to_hit, forward_low)
```

最终 bull 使用严格 `>`，但“首次达标路径”的冻结条件使用 `>=`。这两个比较器必须完全一致，否则 strict-low 会在“恰好碰到阈值”时过早停止观察风险。

**本轮实际执行的最小反例（人工数组，不是实股训练）：**

- `E=10`，+30% 阈值为 13；
- 第 1 日 `high=13.00`（仅等于阈值）、`low=9.00`；
- 第 2 日 `high=13.10`（首次严格超过）、`low=7.00`。

按仓库当前逻辑：第 1 日因 `>=` 冻结 `path_low_to_hit=9`，最终又因第 2 日存在 `>13` 得到 bull=1，strict-low=1，joint=1。

按“首次严格 > 阈值”语义：真正 hit 是第 2 日，其前路径最低为 7 < 8，应当 joint=0。

本轮独立控制流输出：

```text
current_bull=1, current_gate_low=9, current_joint=1
strict_first_hit_day=2, correct_gate_low=7, correct_joint=0
```

**影响：** `label_joint` / `label_strict_low` 的边界样本可被误标；`label_high` 的最终 `>` 本身不因这一点改变。这个错误会传播到 `webpro/low60/low504` 的联合低位标签。

**修复：**若冻结 TaskSpec 是严格 `>`，则 first-hit 也必须：

```python
newly = (~hit) & valid & (high_d > target)
```

更稳妥的是定义一个 `hit_comparator`/TaskSpec 并让 bull 与 first-hit 共用，而不是两处手写。

**验收测试：**至少加入 4 个边界 fixture：`==target 后破低再 >target`、`==target 后始终不 >`、`>target 当日 low 刚好=0.8E`、`>target 当日 low<0.8E`。高/低同日顺序规则必须显式固定。

## EML-P0-SESSION-ALIGN：next stock row 被当成 next market session【确认语义错误】

**固定源码：**

- `src/labels.py::forward_outcomes()`：`entry[:-1] = opens[1:]`，仅以相邻记录同 code 判断；未来 `d=1..H` 也是第 d 个**股票记录**。
- `src/tradeability.py::audit()`：按股票 `shift(-1)` 生成 `next_open/next_high/...`。

这在股票无停牌、无漏数时与市场 session 接近；一旦 `t+1` 市场开市但该股无 bar，当前代码会把更晚的复牌记录当成“下一 session open”，且 H10/H60/H504 的市场时间会被向后延长。

**影响：**

1. 与用户主目标“下一市场交易日 E、H504 市场日”直接不一致；
2. H10 tradeability 可能把延期复牌当成可入场；
3. `no_next_bar=0` 并不能证明每个信号在真正下一市场日可成交，只证明每条 resolved signal 后还能找到一条 stock row。

**修复架构：**

```text
exchange_calendar(session_id, date, open?)
security_state_pit(code, session_id, listed, suspended, board, st_status, known_at)
bars(code, session_id, OHLCV, observation_state)
```

信号日 t 后：`entry_session=t+1`；该市场日没有可成交 open 就标 `entry_unavailable`，不能滑到复牌日。H 个市场日窗口由 session_id 决定；verified suspension 让时钟继续走但不制造价格，未知漏数进入 unresolved/sensitivity。

**验收：**构造 `t=100`、101 停牌、102 复牌的 fixture。entry 必须是 `unavailable@101`，不能变成 102 的 open。另做“整面板漏一个市场日”的反例，H 不得缩短。

## EML-P0-SCANBASE-S1：stride=1 时 natural baseline 与真实 scanned population 不同【确认错误】

**固定源码：**

`src/runner.py::build_scan_targets()` 无论 stride 是否为 1 都先：

```python
_seq = groupby(code).cumcount()
targets = frame[frame["_seq"] >= min_history]
if stride > 1:
    targets = targets[targets["_seq"] % stride == 0]
```

但 `src/scan_all.py::population_baselines()` 当前把 warm-up 条件放在：

```python
if stride > 1:
    seq = frame.groupby("code").cumcount()
    frame = frame[(seq >= MIN_HISTORY) & (seq % stride == 0)]
```

因此 **stride=1 时 baseline 包含每只股票前 60 个 warm-up bar，而 scan targets 不包含**。

**本轮实际执行的人工反例：**2 股 × 65 条记录，`MIN_HISTORY=60`：

```text
真实 scan targets (stride=1) = 10 rows
当前 population_baselines(stride=1) = 130 rows
错误多纳入 warm-up = 120 rows
```

**影响：**当前默认已发布 WebPro `scan_all --stride 5` 不由此反例直接证明受影响；但任何未来 dense stride-1 expert scan 若用此函数，会拿错误 population base rate 算 lift。仓库已经把 ML wide search 切到 stride-1，因此以后专家和 ML 做同人口比较时这个洞尤其危险。

**修复：**warm-up 永远先应用，stride 只决定二次抽样：

```python
seq = frame.groupby("code", sort=False).cumcount()
frame = frame[seq >= MIN_HISTORY]
if stride > 1:
    frame = frame[(seq.loc[frame.index] % stride) == 0]
```

更好：把 `build_scan_targets` 的 selection mask 提取成唯一共享函数，scan 与 population baseline 禁止各写一套。

**验收：**stride=1/5/session-mode 各做合成面板，要求 baseline key set 与 `build_scan_targets` key set 完全一致，再比较 label 统计。

## EML-P0-LOWZONE-LEDGER：先按未来 resolved 筛样本，再谈第一信号【确认设计偏差】

`src/backtest_lowzone.py::run_version()` 首先：

```python
pool = frame[(recall_tier >= version.min_tier) & frame[resolved_col]].copy()
```

然后才在 `pool` 内评估、first-signal-per-year、cooldown/dedupe。这样“未来 H 是否完整”会决定信号日在历史上是否存在于候选池。

对**固定期限、完整队列统计**，只在已 resolved cohort 里算 precision 可以作为一种结果表；但它不能同时充当“实时系统当日会不会发出第一条信号”的 ledger。未来未满 H、退市、未知缺口等不能回到过去删除首信号。

**修复：**把两个账本物理分开：

```text
candidate/signal ledger: t日因果特征 -> score -> policy -> immutable signal_id
outcome ledger: signal_id -> resolved / hit / miss / censored / unknown-gap
```

发布策略先运行，未来 outcome 后关联。已知结果 precision 可以排除 unresolved，但 event recall/coverage 必须同时报告 unresolved 数量及原因。

**验收：**给同一 t 日输入复制两份，只修改 t+300 后的数据完整性，t 日 `signal_id` 和 score 必须完全不变。

## EML-P1-CALIB-TRAIN：发布阈值仍来自 fitted training scores【未修，确认实现】

`src/ml/walkforward.py::evaluate_fold()` 与 `src/ml/final_holdout.py::main()` 都是：

```python
model.fit(x_tr, y_tr)
s_tr = model.predict_proba(x_tr)[:, 1]
thr = pick_threshold(s_tr, ..., target_rate)
pred_te = s_te >= thr
```

这**不是 test-label leakage**，但不是独立校准。对于 RF/HGB 等模型，训练分数分布通常比未来分数更极端；用训练 top-2% score 的绝对阈值去切未来 block，实际发布率会漂移。当前 RF 四折信号量 11,210 / 7,365 / 1,545 / 2,747，已经说明 nominal 2% policy 在不同时期不是稳定容量。

**具体改进：Temporal OOF calibration/policy fit**

在每个 outer train 内再按时间产生 OOF score：

1. inner expanding fit；边界 purge H；
2. 只收集每个 inner future block 的 OOF score；
3. 在 OOF score 上选择 threshold / isotonic / Platt 或“每日预算 K”；
4. 外层模型重拟合全部 outer train；
5. 外层 test 只应用步骤 3 已冻结的 policy。

先不要同时更换 learner；固定 RF 与 HGB 各做 `train-score threshold` vs `temporal-OOF threshold`，才能把“排序能力”和“政策校准”分开。

**验收：**每折记录 nominal 2% 与 realized publish share、precision、event-level precision、Brier/ECE、date-clustered CI。只有 OOF policy 在至少 3/4 folds 同时改善发布率稳定性且不显著牺牲 precision，才保留。

# 3. 本轮模型优化方案：不是再换几个分类器

## 3.1 先冻结两个任务，禁止结果互借

### Task A：仓库 H10 开发任务

- `entry`: 下一**市场 session**的可成交 open（修复后）
- `target`: H10 内 `high > 1.3E` 或 `close > 1.3E` 分开报告
- 用途：短期加速/涨停链/相对强弱研究

当前归档 H10 结果可继续作为开发基线：

- dense wide RF：20.84%，22,867 signals，4/4 folds above base；
- HGB all features：16.44%；
- HGB drop-cross：18.53%。

这些是**开发 OOS folds**，不是新锁箱。

### Task B：用户 H504 主任务

必须另建 TaskSpec：H504 **close > 4E**，低位 gate `low >= 0.8E`，risk-first，同日规则固定，market-session clock，PIT universe。当前 `labels.low504` 使用的是 high-based 4x 与 stock-row clock，不能直接充当主任务标签。

H504 不应从 H10 precision 外推。最多把 H10 OOF score 当一个辅助状态变量，再做独立消融。

---

## 3.2 H10：把 RF 的“排序能力”和“发布策略”拆开

固定当前 RF 配置，不再搜索模型家族；先做：

| 版本 | 评分模型 | policy fit | 目的 |
|---|---|---|---|
| A0 | 当前 RF | fitted-train top2% absolute threshold | 现有基线 |
| A1 | 同 RF | temporal OOF top2% threshold | 去训练分数乐观 |
| A2 | 同 RF | temporal OOF percentile-by-session | 去时期 score drift |
| A3 | 同 RF | temporal OOF top-K/day，K 在 inner folds 选 | 固定每日容量 |

每折同时输出：row precision、event precision、realized publish share、recall、distinct stocks/dates、date HHI、block-bootstrap CI、ECE/Brier。若 A1/A2/A3 只让 signal count 更稳定而 precision 崩溃，也应判失败。

---

## 3.3 专家库：去掉“阈值克隆投票权”，保留机制而非文件数量

当前 36 strategies 中 16 个是 `strict_*`；最新审计已实测 10/16 实际更宽松。把这些二值 selector 当 16 个独立专家进行 ensemble，会让同一个 base score 因复制多个阈值获得不合理投票权。

建议把专家输入变为“机制分量”而不是 36 个二值列：

```text
mechanism_id = base strategy family
z_g(t) = continuous base score / causal primitive vector
binary threshold variants = 只作为诊断，不进入独立投票计数
```

元模型只训练在**时间 OOF expert scores**上：

\[
\operatorname{logit}P(Y=1)=\beta_0+\sum_g \beta_g h_g(z_g)+\gamma^T R_t
\]

其中 `h_g` 可先用单调 isotonic / spline；`R_t` 是市场状态。用 group regularization 限制同一家族重复变量。

对照必须包含：

1. 36 binary expert columns；
2. 去阈值克隆后的 base mechanism binary；
3. base mechanism continuous scores；
4. continuous scores + OOF calibration。

如果 2/3/4 在 3/4 以上 outer folds 不优于 1，或系数跨折大幅换符号，就不继续复杂化。

---

## 3.4 成交性从“事后删除”改成“信号日可预测的执行概率”

当前 tradeability 报告说明 `leader_momentum` 约 15.91% 的 resolved signals 在当前粗略规则下 next-open unfillable。**但事后看到 next-open 再删除**本身是未来过滤，不能作为生产模型提升。

应另训练/建规则头：

\[
p_{fill}(t)=P(\text{entry available at next market session}\mid X_t)
\]

然后比较：

\[
S_{joint}=p_{bull}\times p_{fill}
\]

或在 logit 空间：

\[
S=\operatorname{logit}(p_{bull})+\lambda\log(p_{fill}+\epsilon).
\]

`p_fill` 特征必须全部在 t 收盘已知：当日封板结构、连续板、成交额/换手（若有真实 PIT 数据）、板块制度、ST、停牌公告 known_at 等。next-open 实际状态只作为 label。

# 4. 本轮 3 个待验证新点子（研究假设，不是结果）

## IDEA-EML-07：专家机制去克隆 + 时间 OOF stacking

**依据：**本轮仓库自己已量化证明 10/16 `strict_*` 不是“更严格的新机制”，而是 base score 的更低 cutoff；9/10 precision 更低。继续把它们按文件数计票没有统计独立性。

**实施：**为每个 base strategy 输出 continuous score；所有 threshold clone 映射回 `BASE_STRATEGY_ID`。以 OOF score 训练一个低容量 Logistic/GAM 元模型，family-level L2/group penalty；禁止同一时期直接用 base learner fitted score。

**数据：**现有 expert card + natural scan grid 即可，不需要新行情字段。

**成本：**低到中；主要成本是产生时间 OOF expert score ledger。

**淘汰：**事件级 precision/PR-AUC/校准在至少 3/4 outer folds 无稳定增量，或提升只来自单一市场日期簇，即淘汰 stacking。

---

## IDEA-EML-08：Pre-close fillability head，而不是 post-hoc unfillable filter

**依据：**当前 tradeability 已证实部分高 precision 策略的“下一开盘不可成交”比例明显高于总体；尤其 leader-momentum 98/616 resolved signals 被当前规则判 unfillable。这个问题直接影响“纸面 precision 是否能变成可执行信号”。

**实施：**先修 market-session / PIT price-limit contract，再以 t 时点特征训练 `p_fill`；组合 bull score。所有 `p_fill` 模型选择在 outer-train OOF 中完成。

**数据：**需要 PIT ST/board/listing/suspension/price-limit 规则；没有这些字段时，只能做弱 proxy，不得称真实成交概率。

**淘汰：**若 fillable-event precision 提升的同时 bull event recall 相对下降 >15%，且风险调整后的 coverage/utility 无改善，则不加入主 policy。

---

## IDEA-EML-09：Regime-gated cross features，而不是“全加/全删”

**依据：**dense ablation 中 `drop_cross=18.53% > all=16.44%`，但这只证明当前 HGB 无条件融合 cross 特征不理想，不能证明 cross-sectional 信息永远无效。相对强弱更可能在高横截面离散度/轮动阶段有用。

第一版低容量 gate：

\[
S=f_{abs}(X_{abs})+\sigma(a^T R_t+b)f_{rel}(X_{cross}),
\]

`R_t` 只用 `mkt_dispersion / mkt_vol20 / mkt_breadth` 等 t 日已知量。

**对照：**同一 outer folds、同一 OOF policy 下：`all`、`drop-cross`、`gated-cross`。不要同时换 learner。

**淘汰：**若 regime interaction 在至少 3/4 folds 方向不一致，或 date-clustered CI 不支持相对于 drop-cross 的增量，则保留 simpler drop-cross。
