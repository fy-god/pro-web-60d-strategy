### 新 P1：专家候选信息经过两级管道后被完全擦掉

`EML-P1-H504-EXPERT-CANDIDATE-FEATURES-ERASED-BEFORE-FIT-001`

当前链路：

1. `src/lowzone.py::build_layers()` 产生 `recall_tier` 和大量 causal raw features；
2. `src/ml/research_h504/candidate_manifest.py::build_candidate_manifest()` 只保留 `code/date/recall_tier`，raw family features 全部丢弃；
3. `src/ml/research_h504/task_spec.py::label_h504_candidates()` 再把 `recall_tier` 也丢掉，只保留 candidate_id/code/signal_date 与 outcome 元数据；
4. `src/ml/research_h504/train_h504.py::run_h504_hgb()` 只把 outcome frame 与 snapshot feature frame 合并；
5. `src/ml/research_h504/run.py::_feature_cols()` 的模型列全部来自 snapshot feature frame。

因此当前 T0 的准确描述不是“专家信号 + ML 融合”，而是：

> **由专家规则定义候选总体，然后 ML 只看 snapshot features。**

候选 gate 本身仍有作用，但 `recall_tier`、L1-L5层强度、低位原始 family 特征都没有进入 H504 模型。按当前 CLI，即使后续声称实现 T1=`T0+family raw`，也没有现成的、PIT 安全的 family-raw 输入桥。

这与 v5 的 WP3/WP4 直接冲突：T1-T5 不能只写在任务书里，必须先有 immutable `candidate_id` 键控的 candidate-feature sidecar。

### 新 P2：`down_vol_ratio5` 在当前实现中结构性全 NaN

`EML-P2-LOWZONE-DOWN-VOL-RATIO5-IMPOSSIBLE-MINPERIODS-001`

`src/lowzone.py` 当前写法：

```python
down = np.where(close < prior, volume, np.nan)
up = np.where(close >= prior, volume, np.nan)
down5 = pd.Series(down).rolling(5, min_periods=3).mean()
up5 = pd.Series(up).rolling(5, min_periods=3).mean()
down_vol_ratio5 = down5 / up5
```

同一个 5-row 窗口里，一天不可能同时属于 down 和 up。要让 `down5` 有值需要至少3个 down；让 `up5` 有值又需要至少3个 up；`3+3>5`，所以二者不可能在同一5-row窗口同时 finite。

本轮隔离反例使用40行交替上涨/下跌序列，当前算法得到：

```text
finite(down_vol_ratio5) = 0 / 40
```

这不是“样本少”，而是组合条件本身不可能满足。后续若把这个字段放进 T1/T3，然后由 median/0 impute，模型学到的是缺失编码，不是量压机制。

修复建议：同一完整5-session窗口上分别累计 down/up volume 和 down/up count，再计算条件均值；首版至少要求 `down_count>=2 && up_count>=2`，并保留 count/coverage 作为独立特征。

### 新 P2：当前 low-zone RSI 在单边上涨区间变成 NaN，而不是100

`EML-P2-LOWZONE-RSI-ZERO-LOSS-BECOMES-NAN-001`

`src/lowzone.py::_safe_div()` 在 denominator≈0 时返回 NaN。当前 RSI：

```python
RS = avg_gain / avg_loss
RSI = 100 - 100/(1+RS)
```

因此连续上涨时 `avg_loss=0`，`RS=NaN`，最终 RSI=NaN；平盘窗口 gain=loss=0 也变 NaN。

本轮隔离反例：

```text
monotone rise, RSI14 final = NaN   # current
monotone rise, fixed RSI14 = 100
monotone fall, fixed RSI14 = 0
flat window, fixed RSI14 = 50
```

这意味着 WP3/T4 的“RSI raw 恢复原始量”不能直接复用当前 lowzone RSI 后再用缺失插补；必须先修语义，否则会把最典型的强势单边上涨状态编码成 missing。

## 2. 为什么这条 P1 比“再造一个因子”优先级高

当前 `candidate_manifest.py` 明确执行：

```python
REQUIRED = ("code", "date", "recall_tier")
src = layers.loc[:, list(REQUIRED)].copy()
```

也就是从 `src/lowzone.py` 输出的几十个 causal raw features 中，只留三列。

随后 `label_h504_candidates()` 建 outcome row 时只复制：

```text
candidate_id
code
signal_date
entry_session/deadline/label_end
entry_open/target_price/risk_floor
outcome_class/label_joint/label_resolved
...
```

没有 `recall_tier`。

`run_h504_hgb()` 最终：

```python
data = labels.merge(ff, on=['code','date'], how='left')
```

`ff` 又只来自 `build_research_features(panel)`。

所以当前链路没有任何一步把 expert candidate metadata 重新接回模型矩阵。

### 正确的数据结构

不要把几十个 raw features 塞回 candidate manifest。本轮建议拆成三张不可混淆的表：

```text
candidate_manifest
  candidate_id/code/date/candidate_known_at/version/reason/recall_tier

candidate_feature_sidecar
  candidate_id + allow-listed expert raw features + feature schema/version/hash

outcome_ledger
  candidate_id + entry/outcome/known_at/training_eligible_at/label
```

模型矩阵只在训练边界前按 immutable `candidate_id` 合并：

```text
T0 = snapshot features
T1 = T0 + candidate tier nested indicators + selected expert raw
T2 = T1 + train-only family ECDF
T3 = T2 + MEB/coverage/dominance
...
```

所有臂必须固定相同 candidate IDs、label ledger、fold ids 和 model capacity。

## 3. `recall_tier` 不应只当一个线性整数

仓库已有 `reports/lowzone_baselines.json` 是旧归档口径，不是本次严格 `Close>4E & Low>=0.8E` H504，因此**不能把它当新H504成绩**。

但它能用于检查 tier 的结构假设。其 old low504 归档：

```text
all candidates bull_rate = 4.2099%
tier>=1 = 5.9405%
tier>=2 = 5.5887%
tier>=3 = 5.8857%
tier>=4 = 5.9925%
tier>=5 = 4.1976%
```

明显不是“tier越高越强”的单调序列。因此首轮 bridge 不应只给模型一个 `recall_tier=1..5` 连续整数，然后默认它具有线性/序数几何。

本轮候选编码：

- nested：`candidate_tier_ge_2..5`
- exact one-hot：`candidate_tier_eq_1..5`
- raw family 单独保留，不从 outcome 反推

让模型自己判断不同层级是否有非单调贡献。

## 5. 下一次本机三小时真正该怎么用这项修复

本轮不建议一接入就跑30个fit。先把数据处理做对，再用最少的配对实验判断 expert sidecar 是否有增量。

### Phase A：数据健康与 sidecar（约30分钟目标工作量）

必须输出：

```text
candidate_manifest hash
candidate_feature_sidecar hash
outcome_ledger hash
feature schema hash
fold_plan hash
```

并检查：

- sidecar 与 candidate 一一对应；
- `candidate_known_at <= signal_date`；
- outcome/future字段不在 sidecar；
- `down_vol_ratio5` finite share 不再为0；
- RSI2/14 的 0/50/100 边界语义正确；
- 每个 raw feature 给出全历史 finite share / 年份 / 股票 / 流动性分层。

### Phase B：首个真正有信息量的配对（优先于堆神经网络）

固定同一合法 fold：

```text
A0 = T0 snapshot only
A1 = A0 + candidate tier nested/exact
A2 = A1 + repaired RSI raw + directional volume raw
```

HGB 和 RF 各做同容量配对；若合法 H504 fold 不存在，明确 `BLOCKED_PROTOCOL_H504`，这些模型不缩短标签凑分。

验收不看训练内漂亮分数，必须保存：

```text
full dev predictions
candidate_id/fold_id
TP/signals/precision/recall/base_rate/lift
AP/Brier/logloss
risk/timeout/no-entry/unknown slices
per-date/per-stock concentration
```

如果 A1/A2 没有时间外增量，就保留负结果，不把更多 family 特征盲目堆进去。

### Phase C：才进入 T2/T3 与误差驱动

只有 A1/A2 有可重复增量，才冻结 family mapping，使用 train-only ECDF，再进入 MEB/coverage/dominance。

这样能避免当前最危险的路径：raw字段坏掉 -> median/0插补 -> 模型仍然能fit -> 训练分数看起来上升 -> 实际只是 missingness proxy。
