## 3. 集成测试抓出的新问题 A：原 fold_support 会给出“结构上可切”，但真实候选根本不够

这是本轮最重要的新发现之一，而且来自真实执行候选链，而不是静态猜测。

v4 的 `--stage all` 先用：

```text
fold_support_summary(calendar, calendar)
```

这等价于假设“每个市场日都有一个候选”。在本轮第一次 1180-session 合成集成测试里：

- 日历级检查报告存在大量 legal split；
- 但真正把稀疏 candidate manifest 送入 `run_h504_hgb()` 后，得到 `BLOCKED_PROTOCOL_H504`。

也就是说，**日历长度够，不等于真实候选支持够**。如果把前者保存成唯一 `fold_support.json`，会产生“协议READY、模型却被阻塞”的自相矛盾证据。

v5 修复为两份明确不同的产物：

- `fold_support_calendar_structural.json`：只回答时间轴结构上是否可能完整成熟，`candidate_basis=calendar_structural_one_date_per_session_reference`；
- `fold_support.json`：严格按实际 candidate manifest 重新计算，并记录 candidate rows/stocks 和模型支持阈值。

不再把 calendar reference 称为 candidate-count upper bound，因为横截面上一个session可以有大量候选，candidate数量可能高于“一日一个候选”的日历参考。

## 4. 集成测试抓出的新问题 B：HGB可合法“fit”，但训练样本少于两片叶子的结构下限

v4 T0 使用：

```text
HistGradientBoostingClassifier(
    max_leaf_nodes=7,
    min_samples_leaf=300,
    ...
)
```

但第一合法split只要求 `min_train_candidates=100`。

本轮第一次完整合成链实际得到：

```text
n_train = 108
min_samples_leaf = 300
logloss = 0.693147...
brier = 0.25
```

这不是模型失败本身的问题，而是**支持门槛定义错误**：108条训练样本连一次满足两边各300样本的二叉切分都不可能形成，仍然被记成 `COMPLETE_H504_DEV` 会把“常数叶模型”包装成正常HGB训练。

v5 改为：

```text
min_train_candidates = max(100, 2 * min_samples_leaf)
```

默认 `min_samples_leaf=300` 时，T0至少需要600个训练候选才进入fit；同时 `fold_support.json` 使用同一个模型支持阈值，不再让“支持检查”和“真正模型”使用两套不同门槛。

`--hgb-min-samples-leaf` 仅作为显式研究参数，默认仍为300。合成集成测试为了在较小fixture里验证整链，显式使用20；该数字不代表真实研究推荐值。

## 5. 集成测试抓出的新问题 C：改变HGB参数会错误复用旧完成实验

第二次集成探针中，我把合成HGB的 `min_samples_leaf` 从300改为20后重跑同一个输出目录，发现：

- registry把旧T0 signature判为已完成；
- 新run的 `results=[]`；
- 旧 `metrics.json` 仍留在磁盘；
- run summary反而变成 `BLOCKED_NO_FIT`。

根因有两层：

1. H504 signature 只含 data/candidate/features/horizon，**不含模型超参**；
2. 精确命中已完成signature时直接 `continue`，没有把“复用成功”写回本轮summary。

v5 修复：

- T0 signature 绑定完整固定模型配置：`max_leaf_nodes/min_samples_leaf/l2/lr/max_iter/early_stopping/seed`；
- `Registry.latest_complete(signature)` 返回可复用的真实完成行；
- 精确复用在summary中显式写 `REUSED_COMPLETE`；
- 改超参后signature不同，不能静默复用旧checkpoint/metrics。

这与v4 AUX-TCN已经实现的 training-config hash保持同一原则。

## 6. 任务作用域也必须进入机器结果：H504与AUX不能只靠文件名区分

当前一次 `--stage all` 既可能尝试H504，也可能在H504受阻时继续AUX历史表征。如果仅有一个run级 `evidence_type=REAL_MARKET`，下游很容易把“A股真实历史上的辅助任务”误读成“H504真实市场成绩”。

v5给每个结果/registry行新增显式作用域：

```text
H504_JOINT
AUX_HISTORY
```

因此：

- `REAL_MARKET + task_scope=H504_JOINT` 才属于H504任务；
- `REAL_MARKET + task_scope=AUX_HISTORY` 只表示输入是真实历史，目标仍是辅助表征任务；
- `SYNTHETIC` 永远不能进入实股成绩表。

## 7. T0命名也做了纠正：基线不能偷偷包含研究新增因子

v4 的 H504 `T0` 实际把 `feature_cols` 全部送进HGB，而 `feature_cols` 已包含：

- `vir*`
- `vp_*`
- `kdj_low_*`

这会导致“基线T0”事实上已经消费研究增量，之后无法干净计算T3−T0。

v5 新增 `_baseline_feature_cols()`：

- 保留 snapshot 的价量、长期位置、`kdj_k/kdj_d/kdj_j/kdj_k_minus_d` 等点时信息；
- 排除 `vir*`、`vp_*`、`kdj_low_*` 研究增量。

因此当前T0才真正回到“snapshot baseline”。后续T3可在相同候选/标签/split上加入研究因子做配对比较，不再混合归因。

## 10. 本机三小时执行：下一次应直接跑什么

用户授权的本地执行者接入v5后，先在当前真实本地HEAD上生成 causal low-zone layers。当前产品 `src.lowzone.build_layers()` 本身是明确的因果层实现，V00自然候选是 `recall_tier>=1`。

建议本机工作副本内：

```python
from pathlib import Path
from src.data_pipeline import load_panel
from src.lowzone import build_layers

panel = load_panel()
layers = build_layers(panel)
out = Path("outputs/research_h504/lowzone_layers.parquet")
out.parent.mkdir(parents=True, exist_ok=True)
layers[["code", "date", "recall_tier"]].to_parquet(out, index=False)
```

随后先生成candidate ledger：

```text
python -m src.ml.research_h504.run \
  --stage candidates \
  --layers outputs/research_h504/lowzone_layers.parquet \
  --out outputs/research_h504/LOCAL-3H-01/candidate_manifest.csv \
  --min-tier 1
```

再在同一session运行：

```text
python -m src.ml.research_h504.run \
  --stage all \
  --panel data/panel_daily.parquet \
  --candidates outputs/research_h504/LOCAL-3H-01/candidate_manifest.csv \
  --out outputs/research_h504/LOCAL-3H-01 \
  --evidence-type REAL_MARKET \
  --source-sha <实际本地HEAD> \
  --effective-prompt-sha256 <实际生效prompt hash> \
  --registered-task-timeout-seconds <实际本机读取值> \
  --target-active-seconds 10800 \
  --normal-wall-limit-seconds 12600 \
  --hard-runner-timeout-seconds 13200
```

若实际授权panel仍只有887 sessions，H504 T0预计会按真实candidate support进入 `BLOCKED_PROTOCOL_H504`；同一次 `all` 仍可继续 `task_scope=AUX_HISTORY` 的base-vs-plus TCN。不得把AUX结果写进H504成功率。
