## 1. 对 peer P1 的三处实测更正

### 1.1 浮点表示的子声明**不成立**

peer 18:13 报告 §0 写「合法但未补零的 `1` / `"1"` / **数值型 `1.0`**，candidate manifest 会变成 `"000001"`」。
实测（pandas 3.0.2）：

```text
pd.Series([1.0]).astype(str).str.zfill(6) = ['0001.0']      <-- 不是 '000001'
pd.Series([1]).astype(str).str.zfill(6)   = ['000001']      <-- 这个对
pd.Series(['1']).astype(str).str.zfill(6) = ['000001']      <-- 这个对
```

`zfill(6)` 补齐到宽度 6 **含小数点**，所以 `1.0` 得到的是 `"0001.0"`，一个既不等于 panel 的 `"1.0"`、也不等于 candidate 目标的 `"000001"` 的第三种键。
**因此 `1.0` 不可作为该 P1 的证据引用。**

### 1.2 方向反了：补零的一方才是合规的一方

peer 把缺陷归为「`candidate_manifest` 补零」。实测该模块的行为是**被测试锁定**且与仓库其余 5 处一致的：

- `tests/research_h504/test_candidate.py:415-428` **断言** `['1','2'] → ['000001','000002']`
- 另有 5 个模块补零：`data_pipeline.py:53`、`hitrate_vs_expectancy.py:74`、`live_readiness.py:149`、`tradeability.py:153`、`make_charts.py:244`
- 只有 `data_io.py:25` 与 `task_spec.py:57,65` 不补

`task_spec.py:38-100` 的 docstring **没有**任何键格式意图说明，因此「谁错」不能从文档推出。
更准确的表述是：**`data_io`/`task_spec` 未做 canonicalization**，而不是 `candidate_manifest` 多做了。

### 2.2 触发条件 / 反例（实测）

我用真实 `label_h504_candidates` + `run_h504_hgb`（自 `D:\eml_h18_tip` 导入）构造 60 只票 × 30 天、胜负各半的面板，使标签侧**完全正常**（`870 success / 870 risk`），只让**特征帧**用未补零键：

```text
arm A  特征匹配率 = 0.0000  ->  status = COMPLETE_H504_DEV
       logloss = 0.6931471805599454   brier = 0.25   average_precision = 0.5
arm B  特征匹配率 = 1.0000  ->  status = COMPLETE_H504_DEV
       logloss = 0.11785143476351961  brier = 0.012359193181321886  average_precision = 1.0
arm C  键匹配但特征为纯噪声 ->  status = COMPLETE_H504_DEV
       logloss = 0.7000778416543246   brier = 0.2533112985805458  average_precision = 0.5157287315325664
```

`ln(2) = 0.6931471805599453`；A 的 `logloss` 与之相差 `1.11e-16`（浮点内相等），`brier=0.25`、`AP=0.5` 正是 `p≡0.5` 常数预测器的精确三元组。
**A 与 C 的 `status` 完全相同**，因此「特征全丢」与「诚实的无信号」在下游可观测面上**不可区分**；`metrics.json` 的键中不含任何 `match`/`join`/`nan`/`coverage` 字段。
