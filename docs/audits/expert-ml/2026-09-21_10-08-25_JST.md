### 4.2 强制中断→resume 的真实软件行为

我在沙箱构造 24 个合成股票、320 sessions，只为测试流水线和续跑，不用于任何市场结论。运行：

```text
python -m src.ml.research_h504.run \
  --stage all \
  --panel evidence/v3_run/panel.csv \
  --out evidence/v3_run/out \
  --horizon 504 \
  --seeds 17,29 \
  --max-epochs 3 \
  --patience 2 \
  --batch-size 256 \
  --max-aux-fits 4
```

外层执行限时在第4个 AUX fit 完成前杀死首轮进程。此时 `experiment_registry.jsonl` 已存在3个 `COMPLETE_AUX`。用**完全相同命令**再次执行，registry 跳过已完成的三个 signature，仅补齐第4个 fit；最终 registry 共4个完成记录。这证明候选至少具备了用户三小时工作真正需要的“被外层中断后不从零重复”的基本能力。

合成软件诊断结果如下，仅用于验证训练/保存/复用链：

| representation | seed | ret-up log-loss | Brier | log-RV5 RMSE | epochs |

| base | 17 | 0.69556 | 0.25120 | 0.17819 | 3 |
| base | 29 | 0.69835 | 0.25259 | 0.17552 | 3 |

## 6. 本地 agent 下一次必须先跑什么

在已有授权隔离副本内，先不要再写另一篇研究计划。应用/移植候选 v3 后，首个可验收命令应类似：

```bash
python -m src.ml.research_h504.run \
  --stage all \
  --panel <真实授权panel> \
  --candidates <真实PIT低位候选manifest，若已经存在> \
  --out <新的不可变run目录> \
  --seeds 17,29,43 \
  --max-epochs 30 \
  --patience 5 \
  --max-aux-fits 6
```

如果本机没有显式 candidate manifest：

- H504 分支必须 `BLOCKED_CANDIDATE_MANIFEST`；
- 不准把所有行改成候选；
- 仍运行真实 panel 的 factor diagnostics 和 AUX 表征；
- 同时从当前生产候选/专家/低位规则链生成PIT candidate manifest，再回到H504。

如果 calendar 对 full-followup H504 无合法 fold：

- H504 分支必须 `BLOCKED_PROTOCOL_H504`；
- 不准把504改60/10，不随机切分；
- AUX-TCN只作为历史表征诊断；
- 继续查找已授权更早历史并重新生成 `fold_support.json`。

## 7. 下一优先实验，不新增机制名称

**优先实验：先验证执行链本身。**

- 有合法H504 fold和显式候选：先跑 T0 HGB，得到第一张真正 H504 完整预测表，再增加 KDJ-path/pressure/VIR 单组；

淘汰条件：同条件配对 log-loss/Brier/AP 没有稳定方向、增量主要来自coverage/mask、或跨时间块翻向，则该分量不进入下一层。
