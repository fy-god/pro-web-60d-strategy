# 2. 错误与风险清单

## P0 — EML-P0-THRESH-CAL：发布阈值来自“拟合自身训练集”的分数，不是独立时间校准

**位置**：[`src/ml/walkforward.py`](https://github.com/fy-god/pro-web-60d-strategy/blob/2f2945bedcfff20deceb85b076d839b2e8f6633a/src/ml/walkforward.py)，函数 `evaluate_fold()` / `pick_threshold()`。

当前逻辑的关键最小片段是：

```python
model.fit(x_tr, y_tr)
s_tr = model.predict_proba(x_tr)[:, 1]
s_te = model.predict_proba(x_te)[:, 1]
thr = pick_threshold(s_tr, y_tr, cfg.target_rate)
pred_te = s_te >= thr
```

这里没有把 test label 用来选阈值，所以**不是传统测试泄漏**；但阈值是从模型已经拟合过的同一批 `x_tr` 的 in-sample score 分布取得。树模型的训练分数分布通常比未来 score 更尖锐，而且市场 regime 会移动 score 的绝对标度。于是 nominal `target_rate=0.02` 并不意味着未来约发布 2%。

仓库的 RF 结果正好显示这种不稳定性：`fam_rf_5` 的 4 个 OOS fold precision 为 22.88 / 18.36 / 18.06 / 20.71%，但信号数为 **11,210 / 7,365 / 1,545 / 2,747**。precision 跨期相对稳定是好事；发布密度漂移却说明“训练 score 的 98% 分位阈值”不是稳定的未来政策。

### 影响

- RF 20.84% 是有效的历史 OOS 诊断，但目前的 threshold policy 不是一个经过独立 calibration 的生产规则。
- 不同模型的 in-sample overfit 程度不同，使用各自训练 score 分位数会把“模型排序能力”和“训练分数膨胀程度”混在模型比较里。
- 后续若做 ensemble / meta-model，这个问题会继续传递到第二层。

### 修复方案

先做一个**最简单、可解释的 outer fit / calibration / test**：

1. 对每个 outer fold，只使用 outer-train。
2. outer-train 的最后 20% 市场 sessions 作为 calibration block；fit 与 calibration 中间 purge `H+embargo=12` sessions。
3. 基模型只在 fit block 拟合。
4. 用 calibration **预测分数**选择固定 publication budget（例如 calibration top 2%），或用 isotonic / Platt 做概率校准。
5. 完全冻结模型和阈值，再评分 outer-test。
6. 第一版不要“校准后又用 fit+calibration 重训模型”，否则 score scale 又变了；若要重训，必须另做“cross-fitted calibration map”实验。

### 验收 / 证伪

同一个 RF 配置，现行规则 A 与 temporal-calibration B 同队列比较：

- 每 fold：test rows、signals、publication share、TP、precision、recall、PR-AUC、Brier/ECE；
- 报告 publication share 的 fold CV / max-min；
- B 若仅让信号数量稳定但 precision 明显下降，也要如实淘汰；
- 预注册判据建议：先要求 4/4 folds publication share 不再出现数量级漂移，再看 precision 是否保持；不能以事后调 publication rate 刷高 precision。

## P0 — EML-P0-EVENT-LEDGER：6202 个 holdout row 信号不是 6202 个独立事件，缺少因果“首信号 / 冷却”账本

**位置**：[`src/ml/final_holdout.py`](https://github.com/fy-god/pro-web-60d-strategy/blob/2f2945bedcfff20deceb85b076d839b2e8f6633a/src/ml/final_holdout.py)。

当前核心仍是：

```python
pred = s_te >= thr
n = int(pred.sum())
hits = int(y_te[pred].sum())
```

机器可读结果是 **6,202 signals / 844 hits / 13.61% / 1,194 stocks / 150 dates**。同一股票可以连续多日超过阈值，每个 stock-day 都计一条 signal。H10 label window 又高度重叠，所以这些行既不是独立机会，也不是用户最终要的“首次触发事件”。

### 影响

- 行级 precision 仍是一个合法的 score-policy 指标，但不能直接解释为“6,202 次独立预警中 13.61% 成功”。
- 有效样本量比 6,202 小；目前只按日期 block bootstrap，仍未处理同股重复。
- 策略如果真正只在第一次触发时行动，真实 event-level precision / recall 可能明显不同。

### 修复方案

把 `score ledger` 与 `outcome ledger` 分开：

```text
stock,date,score,threshold,policy_state,signal_id
```

**先**按当时可知数据运行状态机，再关联 H10 future outcome。首版用最容易解释的政策：

- `IDLE -> SIGNAL`：首次 `score >= threshold`；
- `SIGNAL -> COOLDOWN`：发布后进入与 H10 对齐的 10-session 冷却；
- 冷却结束才可再发布；
- 冷却状态只由历史信号时间决定，不允许未来 hit/miss 决定是否去重。

同时保留 row-level 指标作诊断，但 headline 增加 event-level TP/N、event recall、distinct stocks/dates。

### 回归验收

“全年回放后切出 2026”必须与“携带 2025-12-31 状态，从 2026 在线继续回放”产生完全相同的 signal_id/date。任何结果不一致说明状态机使用了未来信息或 reset 错误。

# 3. 当前模型应怎样优化：不是继续换分类器

## 3.1 先固定可信评价层

顺序必须是：

1. dense stride-1 + 固定 label/task；
2. outer fit / calibration / test；
3. event ledger；
4. PIT tradeability；
5. 同队列比较模型；
6. 最后才做 ensemble。

否则每换一个模型，阈值尺度、重复信号密度和可成交性都跟着变，模型差异与政策差异混在一起。

## 3.2 以 RF 作为当前 H10 挑战基线，但先校准它

仓库归档 `fam_rf_5`：20.84%，22,867 OOS row-signals，4/4 folds 高于各自 base；这是当前模型族搜索中最强且相对稳定的历史证据。下一轮不要立即加 XGBoost/Transformer；先回答：

> RF 的优势来自真正排序能力，还是 in-sample threshold + regime score scale 的组合？

只改变 threshold-calibration，一切其他保持 RF 不变。若 temporal calibration 后 RF 仍显著领先 HGB，才把 RF 作为后续 ensemble 主干。

## 3.3 对 cross features 不要简单“删掉”，先测试冗余 / regime 依赖

Dense ablation 中：all=16.44%，drop-cross=18.53%；但 cross-only 本身约 15.14%。这说明 cross 组不是“完全无信息”，更像是与 raw volatility/momentum 重复，或在不同 market regime 中方向不稳定。

因此下一实验应是“drop-cross”之外的结构化对照：见 IDEA-02。

## 3.4 H504 主目标必须新建 TaskSpec，不能直接迁移 H10 数字

H504 要独立实现：`entry_session=t+1 market session`、`close>4E`、`risk-first low<0.8E`、timeout、unresolved、event-known-at、生存暴露和 signal ledger。H10 模型最多作为 auxiliary feature，不能当标签替代。

# 4. 待验证的新点子（研究假设，不是已证提升）

## IDEA-EML-01：Temporal OOF calibration —— 把“模型排序”与“发布预算”解耦

### 机制
当前阈值取 fitted-training score 的分位数。RF/HGB 的 in-sample score 分布与未来不同，导致 publication rate 漂移。

### 实现
第一版不引入复杂 conformal：outer-train 最后 20% sessions 做 calibration，purge 12 sessions；fit-only 训练模型，calibration-only 选阈值。第二版再尝试 rolling OOF score + isotonic calibration。

### 对照
A 当前 in-sample threshold；B temporal quantile calibration；C temporal isotonic + fixed probability threshold。模型、特征、outer folds 完全相同。

### 淘汰
若 B/C 不能显著降低 fold publication-rate 漂移，或 precision / recall 同时恶化且无校准改善，停止投入。

---

## IDEA-EML-02：Regime-gated relative features —— 解释“cross-only 有信息、加入全特征反而变差”

### 机制
相对强弱在高横截面离散度/轮动市场可能有用，在普涨普跌或低离散度时可能只是 raw feature 的噪声复制。

### 最小实现
不要先上神经 gating。先做两模型：

- `f_abs`: 删除 cross 的模型；
- `f_rel`: 只用 cross 的模型。

用 calibration block 上可知的市场状态 `R_t=[mkt_dispersion, mkt_vol20, mkt_breadth]` 划分 2–3 个预注册 regime（分位点只能在 calibration 拟合），分别比较 `f_abs` 与 `f_rel`；若确有稳定条件差异，再测试：

\[
s_t = f_{abs}(x_t) + \sigma(a^T R_t+b)\cdot f_{rel}(x_t)
\]

`a,b` 只能在 development/calibration 估计。

### 淘汰
没有至少 3/4 outer folds 出现同方向 regime interaction，或 gated 模型在 event-level precision/PR-AUC/校准中均无稳定增益，就保留简单 drop-cross。

## IDEA-EML-03：OOF H10 score 作为 H504 的“短期启动状态”辅助特征

### 目的
利用本仓库已经测到的 H10 排序信号，但不把短期任务冒充长期四倍目标。

### 实现
在 H504 candidate day `t`，只允许使用一个由**过去数据训练**的 H10 模型给出的 OOF / live-like score：`activation_score_h10(t)`。它与 KDJ、长期 position、波动率、低位结构一起进入 H504 baseline。

对照：

- H504 baseline（KDJ + position + volatility + market）；
- H504 baseline + causal H10 score；
- H504 baseline + 随机置换 H10 score（负控制）。

### 淘汰
若在真正时间外 H504 event-level 联合 precision、event recall、PR-AUC / survival concordance 都无稳定增量，删除该桥接特征。绝不使用 H10 in-sample score。

# 5. 下一组最小实验矩阵

| 实验 | 只改变什么 | 主指标 | 必须同时报告 | 通过/淘汰重点 |
|---|---|---|---|---|
