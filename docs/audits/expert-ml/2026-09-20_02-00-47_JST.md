## 1.1 新的 P0：`git fetch` 已经真实失败，但顶层仍发布 `PASS`

当前 `reports/AUDIT_STATUS.md` 明确同时写着：

```text
Verdict = PASS
Consistency check = exit code 0
629 checks run, 0 problem(s)
Remote drift = git fetch failed (exit 1):
  error: fetching ref refs/remotes/origin/main failed:
  incorrect old value provided
```

这比上一轮“有 drift 仍 PASS”更严重：当 `git fetch` 失败时，本地连“远端现在是什么树”都不能可靠知道，仍然运行本地 checker 并发布 PASS。

### `EML-P0-AUDIT-FETCH-FAIL-PASS` — P0，新增确认

固定源码：`32155ecae1a0a0be1877b780df0da12354c347ea`

`scripts/scheduled_report_audit.py::changed_reports()` 当前：

```python
code, out = run(["git", "fetch", "origin", "main", "--quiet"])
if code != 0:
    return [], f"git fetch failed (exit {code}): ..."
```

返回的是“空 changed 列表＋错误文字”。随后：

```python
ok = code == 0 and not unstable
verdict = "PASS" if ok else "ATTENTION"
```

这里的 `code` 是 `audit_reports.py` 的退出码，不是 fetch 退出码；fetch 失败只被塞进 `note`，不进入 PASS 条件。因此当前真实生产状态就是“remote fetch failed + PASS”。

**影响：** 任何 stale local checkout 都可能被认证；`PASS` 不能说明它对应 GitHub 当前 `main`。

**修复：** report-audit 必须把同步状态作为一等状态，并冻结被审计 SHA：

```text
fetch != 0             -> SYNC_FAILED，禁止 PASS
fetch == 0
  -> AUDITED_SHA=origin/main
  -> detached worktree@AUDITED_SHA
  -> checker
  -> 发布前再次读取 remote HEAD
  -> remote changed     -> STALE，重跑
  -> checker != 0       -> FAIL
  -> checker == 0       -> PASS(audited_sha=...)
```

回归输入至少覆盖 fetch 失败、fetch 成功但远端在 checker 后变化、checker 自身失败、artifact 审计中途变化四类。

这条 P0 阻断“正式发布认证”，**不阻断隔离副本里的 H504 因子开发和合法开发折训练**；下一轮不能再把全部时间耗在 report publisher 上。

**研究策略：** 即使最终认证块不足，仍可在明确标为开发探索的合法成熟队列上跑 M1–M5、因子调试和消融；不能把“没有 pristine final test”解释成“本地什么都不训练”。

## WP6 — MLP 与 TCN 实际训练

**待新增：** `models.py`, `sequence_dataset.py`, `train_nn.py`。

M4 snapshot MLP：`input -> 64 -> 32 -> 1`，ReLU/GELU 二选一先固定 ReLU，dropout 0.1。

M5 causal TCN：过去 128 market sessions，width=32、kernel=3、6 个 residual blocks，每块 2 个 causal conv，dilation=`1,2,4,8,16,32`，dropout=.1，最后时点读出＋同样 snapshot branch。

该配置的理论感受野：

```text
RF = 1 + 2 conv/block * (kernel-1) * sum(dilation)
   = 1 + 2*2*(1+2+4+8+16+32)
   = 253 sessions
```

因此覆盖 128 输入窗口；必须再用“改变输入前缀不得影响更早预测”的单元测试检查 causal padding。

序列只允许历史价格变换、KDJ、位置、量压、mask、gap/time-delta；禁止 entry、未来 outcome 和任何 after-t 字段。索引懒加载或 memmap，不把 2.68M 行展开成巨大重叠 tensor。

训练起点：AdamW `lr=1e-3, weight_decay=1e-3, max_epoch=30, patience=5, grad_clip=1`；先 128–512 条训练样本做 overfit sanity，再跑真实时间留出。1–2 epoch 只能叫 smoke。

保存 `best/last`, optimizer/random state, epoch loss, lr, pre-clip grad norm, params, device, peak memory, train/inference time, full dev predictions。

缺 torch -> `BLOCKED_ENV`，继续 M1–M3，不自动安装/改全局环境。
