## 0. 本轮结论

本轮新增一条**默认 REAL_MARKET 路径可达的 P1**：

### `EML-P1-H504-CALENDAR-FILLER-ROW-POISONS-RECURSIVE-KDJ-STATE-001`

当前 H504 真实运行链在提供独立市场日历后，会先在 `data_io.prepare_panel()` 中把每只股票从其首条到末条记录之间的缺失市场 session **物化成全 NaN OHLCV 行**；随后 `run.py` 直接把这张重索引后的 panel 交给 `build_research_features()`。

默认 richer feature 路径又会调用 `src.ml.build_matrix.add_price_features()`，后者调用 `src.features.kdj()` 的手写递归 K/D 状态。

在一条 filler 行上：

1. 最近 9 个观测窗口的 `high/low` 仍可能给出有限 rolling span；
2. 该 filler 行 `close=NaN`；
3. `rsv[valid] = (close-low_n)/span*100` 因而变成 `NaN`；
4. 手写递归 `k_prev = 2/3*k_prev + 1/3*rsv[i]` 立即变成 `NaN`；
5. 后续即使重新有真实成交 bar，`NaN` 状态继续参与递归，**该股票之后全部 K、D、J 永久 NaN**。

这不是“停牌日那一行缺特征”，而是**一次缺失 session 可以销毁该股票此后全部递归 KDJ 状态**。随后 `add_kdj_path_features()` 对 `NaN < 20` 的比较得到 `False`，还会把低位路径状态向 0/无低位方向扭曲。

该错误与此前已经登记的 `missing_bar provenance` 问题同源——都是“把日历 filler 行永久塞回股票 panel”造成——但本轮新增证据是：**filler 不只改 outcome provenance，还会破坏默认 T0/plus_research 的真实特征状态。**

## 2. 新 P1：calendar filler 会永久毒化递归 KDJ

### 2.1 入口 1：`prepare_panel()` 真的会物化 NaN bar

文件：`src/ml/research_h504/data_io.py`

真实路径：

```python
for code,g in p.groupby('code',sort=False):
    span=cal[(cal>=g.date.min())&(cal<=g.date.max())]
    h=g.set_index('date').reindex(span)
    h.index.name='date'; h['code']=code
    groups.append(h.reset_index())
```

这意味着某股票在独立交易日历中的停牌/缺档 session，只要位于该股票首末两条记录之间，就变成：

```text
code = 真实股票代码
date = 真实市场日
open/high/low/close/volume = NaN
```

注释虽然写着“Missing sessions remain NaN; never ffill prices”，但**“不 forward-fill”并不等于“可以把 NaN filler 当作 feature builder 的一条 bar”**。

### 2.2 入口 2：runner 把 filler panel 直接交给 feature builder

文件：`src/ml/research_h504/run.py`

顺序是：

```python
panel,cal=prepare_panel(_read_table(args.panel),independent_cal)
...
feat,feature_source=build_research_features(panel)
```

因此在 REAL_MARKET / AUX_REAL_HISTORY 且提供 `--calendar` 的默认正确用法下，重索引 filler 不是测试边角路径，而是**真实运行默认路径**。

### 2.3 入口 3：默认 richer snapshot 确实走手写递归 KDJ

文件：`src/ml/research_h504/snapshot_features.py`

`build_snapshot_features()` 优先：

```python
from src.ml import build_matrix as bm
frame = panel.sort_values(['code','date']).reset_index(drop=True).copy()
...
price = bm.add_price_features(frame)
```

只有 `ImportError/AttributeError` 才退回 minimal fallback；当前仓库 `src/ml/build_matrix.py` 存在，因此正常环境会进入 richer path。

文件：`src/ml/build_matrix.py`

`add_price_features()` 在构造价格特征时调用：

```python
from src.features import kdj
kdj_frame = kdj(frame)
```

### 2.4 入口 4：`src.features.kdj()` 的 NaN 状态不可恢复

文件：`src/features.py`

核心逻辑：

```python
rsv = np.full(len(out), 50.0)
valid = span > EPS
rsv[valid] = (close[valid] - low_nv[valid]) / span[valid] * 100.0
...
k_prev = (1.0-k_smooth)*k_prev + k_smooth*rsv[i]
d_prev = (1.0-d_smooth)*d_prev + d_smooth*k_prev
```

filler 行经 rolling `high/low` 后 `span` 往往仍有限，所以会进入 `valid=True` 分支；但本行 `close=NaN`，导致 `rsv[i]=NaN`。手写状态递归没有 `np.isfinite(rsv)` guard，也没有“缺 bar 时保持前一状态”的分支，因此 K/D 从这一行起永久 NaN。

这与 `src/features.py` 自己模块级契约“Suspended sessions are simply absent from the source data; we never forward-fill or invent a bar”正面冲突：H504 runner 在进入该模块前已经把缺 session 重新物化成一行了。

## 4. 影响范围

### 4.1 默认 H504 T0 受影响

`_baseline_feature_cols()` 明确保留普通 KDJ / price-position 特征，只排除 `vir*`、`vp_*`、`kdj_low_*` 等研究增量。因此 richer snapshot 中的 `kdj_k/kdj_d/kdj_j/kdj_*chg5` 属于 T0 的候选输入。

一旦某股票历史中出现一次 calendar 内缺 bar：

- KDJ 后续永久 NaN；
- HGB 的 `_safe_impute()` 会把这些 NaN 用 train median / 0 处理；
- 模型看到的不再是该股票真实 KDJ 状态，而是系统性缺失/中位数代理。

这会把“曾经发生过一次停牌/缺档”变成长期模型状态污染。

### 4.2 KDJ path 增量受影响更直接

`add_kdj_path_features()` 用：

```python
low = ((out['kdj_k']<20)&(out['kdj_d']<20)).astype(float)
```

在 pandas/numpy 语义下，`NaN < 20` 为 `False`。所以递归 KDJ 被毒化后，后续 `kdj_low_occ_* / kdj_low_streak` 不只是 NaN，而会被向“不是低位”方向编码。

因此 T3/T4/T5 若以后正式接入，会继承更隐蔽的方向性错误。

### 4.3 与 missing-bar provenance 共用一个结构根因

此前已登记：永久 filler 行会让 label oracle 的 `present = cal.isin(g.index)` 把真正 missing bar 看成“日期存在但价格缺失”。

本轮新增：同一 filler 又会进入 feature builder，毒化 KDJ 状态。

所以正式修复不应该再分别给 labeler 和 KDJ 打局部补丁；应该拆分**两种数据形态**：

- `observed_bar_panel`：只含真实股票 bar，给 feature builder；
- `market_calendar`：独立市场 session 序列，给标签 deadline、t+1、t+504 和 gap 检查；
- label oracle 内部可以临时对齐，但不得把 filler grid 回灌给递归 bar-state feature builder。

## 5. 建议的窄修复

### 5.1 不再把 reindexed filler panel 作为统一 panel

建议把现有 `prepare_panel()` 拆成或等价实现：

```text
validate_observed_panel(raw_panel, calendar)
    -> observed_panel（不 reindex）
    -> independent_calendar
```

H504 oracle 已经在 `label_h504_candidates()` 内部按股票执行：

```python
aligned = g.reindex(cal)
```

因此为了 label scan，没有必要事先把整个 panel 永久重索引一次。

### 5.2 `market_session_id` 必须来自独立 calendar，而不是 observed-date union

不能简单删除 filler 后继续调用当前：

```python
add_market_session_id(frame)
```

因为它按 `frame.date.drop_duplicates()` 重新编号；如果某日全体授权子宇宙都缺 bar，或者某股票停牌，gap-sensitive 因子会把 gap 压平。

应新增：

```python
attach_market_session_id_from_calendar(observed_panel, independent_calendar)
```

把每个真实 bar 的 date 映射到独立 calendar position。

这样：

- KDJ / ret / rolling bar-state 只在真实 bar 上推进；
- VIR 仍能看到 `49 -> 51` 的两步跳跃，并拒绝把 20-row window 当作连续 20 market sessions。

### 5.3 追加回归与 mutation tests

最少加入：

1. 单股票中间缺 1 个 market session，重开后 KDJ 必须有限；
2. 缺 session 本身不得出现在 observed feature rows；
3. external `market_session_id` 必须保留 jump=2；
4. prefix future perturbation 不得改变 cutoff 之前特征；
5. 删除 observed-only 分离后，poison test 必须变红；
6. label oracle 对同一缺 session 仍必须保留 `unknown_missing_bar` provenance，而不是 `unknown_missing_price`。
