# 2. P0 / P1 / P2 错误定位

## EML-P0-COOLDOWN-GRID：cooldown 用的是“signal-date grid”，不是 exchange-session grid【新确认错误】

**固定源码：** `6bc7fa2.../src/labels.py::dedupe_signals()`。

当前代码：

```python
session_index = {d: i for i, d in enumerate(sorted(out["date"].unique()))}
positions = out["date"].map(session_index).to_numpy()
...
if last is None or (positions[j] - last) >= cooldown:
    keep[j] = True
```

而 `score_signals()` 传给 `dedupe_signals()` 的 `live` 已经是**信号行**，不是全市场日历，也不是完整 panel。因此 `sorted(out["date"].unique())` 只包含“至少有一个信号出现的日期”。

新增测试 `test_dedupe_cooldown_boundary_is_inclusive()` 自己也写明了这一事实，并专门塞了一个 filler stock 在每个中间 session 造出 dense date grid，才让 60-session 边界测试成立。这个 fixture 能测试 `>=` 边界，却同时证明生产函数本身没有真正 market-session clock。

### 本轮亲自执行的最小反例

人工构造 80 个工作日，但全体信号帧只在 `[0,5,10,15,20,25,30,40,50,60]` 这些实际 market-session 上出现过信号。某只股票在 day 0 与 day 60 各发一次信号：

```text
真实市场 session 距离 = 60
当前 dedupe positions 距离 = 9
```

若 `cooldown=60`，第二条应当在真实 60-session 边界被保留；当前实现会继续压掉它。

更严重的是：给**别的股票**增加/删除中间日期的信号，会改变该股票的 `positions` 距离，从而改变它自己是否过 cooldown。也就是说，一个股票的发布状态会被无关股票的信号密度影响。

### 影响

1. H10/H60/H504 的 deduped precision、signal count、event recall 都可能偏移。
2. 市场平静期信号稀疏时 cooldown 被无意拉长，事件召回下降；市场活跃期全市场每天都有信号时才接近真实 session 计时。
3. 同一模型、同一只股票的信号政策会随其他股票是否产生信号而改变，不满足因果发布策略的独立性。

### 修复

把 `market_session_id` 在**过滤信号之前**写进 panel/ledger，禁止在信号子集上重新编号日期：

```python
def dedupe_signals(signals, cooldown, session_col="market_session_id"):
    if session_col not in signals:
        raise ValueError("market_session_id required for production dedupe")
    ...
    if session_id[j] - last_session >= cooldown:
        keep[j] = True
```

更推荐把 cooldown 从“后处理统计函数”提升为 immutable signal ledger 的发布状态机：

```text
t 日 causal candidate -> score -> threshold ->
per-code last_publish_session -> publish/suppress -> immutable signal_id ->
未来 outcome 关联
```

### 回归验收

必须新增 4 个测试：

1. **Sparse signal dates**：同股 day0/day60，期间完全无其他信号，仍保留 day60。
2. **Cross-stock invariance**：增删别的股票信号，目标股票的 dedupe 结果完全不变。
3. **59/60 边界**：59 suppress，60 keep。
4. **Holiday / suspension**：market calendar 决定 session id；停牌股票自身没有 bar 也不能让市场 clock 停止。

# 3. 细致模型改进方案

这一轮没有新的市场训练，因此模型方案不做“换算法排行榜”，先把**评价策略和发布策略**修成不随数据子集漂移，再进行优化。

## 3.1 第一阶段：TaskSpec / event-policy contract 先封死

优先顺序：

1. strict `>` first-hit comparator 一致化；
2. 独立 market calendar，entry 与 horizon 全部使用 `market_session_id`；
3. cooldown 使用 market-session id，不使用 signal-date grid；
4. candidate ledger 先冻结，再关联 outcome；
5. stride / warm-up population mask 只保留一份共享实现。

这五项全部属于**修 bug / 修评价契约**，不能计作模型精度提升。

## 3.2 第二阶段：Temporal OOF calibration，而不是 fit-set quantile

当前 `src/ml/walkforward.py::evaluate_fold()`：

```python
model.fit(x_tr, y_tr)
s_tr = model.predict_proba(x_tr)[:, 1]
thr = pick_threshold(s_tr, y_tr, target_rate)
pred_te = s_te >= thr
```

没有 test-label leakage，但 threshold 来自同一模型的 in-sample score 分布；当前 RF 四折 signal count 为 11,210 / 7,365 / 1,545 / 2,747，未来发布密度显著漂移。

建议每个 outer fold 再拆成：

```text
fit block -> purge(H+embargo) -> temporal calibration block -> outer test
```

- 模型只在 fit block 拟合；
- threshold / calibration mapping 只看 calibration block；
- outer test 一次性评估；
- calibration block 不参与 model.fit。

两种 policy 都跑：

**A. 固定发布预算**

```math
q = Q_{1-r}(s_{cal}),\quad publish = 1[s_t \ge q]
```

**B. Precision-LCB policy**

在 calibration 中按 score bucket 求 Wilson / cluster-bootstrap precision LCB，选择满足最低样本支持的最高可发布 bucket；若支持不足就 abstain，而不是硬选阈值。

验收不只看 pooled precision，还要比较：

- 4 fold signal-share dispersion；
- 每 fold TP / signals；
- distinct stocks / dates；
- calibration error；
- clustered CI；
- 与原 fit-quantile policy 的同 test block 差值。

若 OOF calibration 不能在至少 3/4 outer folds 降低发布率漂移，并且 pooled precision / recall 没有稳定改善，则不引入生产链。

## 3.3 第三阶段：expert mechanism de-cloning

当前 36 个专家中大量 strict variant 只是同一机制不同阈值，不能把 36 个二值票当 36 个独立信息源。

建议建立：

```text
strategy_id -> base_mechanism_id -> continuous mechanism score
```

只保留每个 base mechanism 的连续 score，先做：

1. base mechanism 单变量 OOS；
2. mechanism pair correlation / mutual information；
3. temporal OOF Logistic / GAM / sparse group model；
4. threshold 在独立 calibration block 冻结。

对照：

```text
36 binary votes
vs deduped base binary votes
vs continuous mechanism scores
vs temporal-OOF stacking
```

若 stacking 的增量只来自某一个时间 fold，或去掉重复阈值版本后消失，则判定原“多专家优势”主要是 threshold cloning，不保留复杂元模型。

# 4. 本轮待验证新点子

## IDEA-EML-07：Calendar-invariant event policy

### 动机

本轮 cooldown bug 说明“事件定义”仍依赖信号数据本身。先把事件发布政策写成独立、可重放的 market-session state machine，才有资格比较模型。

### 实现

新增 immutable ledger 字段：

```text
signal_id, code, signal_session_id, score, threshold_version,
policy_version, last_publish_session_before_t, publish_decision,
suppress_reason, feature_asof
```

任何 outcome 字段禁止进入这个表；结果另表按 `signal_id` 关联。

### 对照

同一 score 序列比较：

1. 当前 signal-date-grid cooldown；
2. market-session cooldown；
3. market-session cooldown + first-signal-only；
4. market-session cooldown + fixed 20/60/120 session policy。

### 验收 / 淘汰

- Cross-stock invariance 必须 100% 成立；
- 任意删除未来 outcome 行，历史发布 ledger 不得改变；
- 若修正后 H10/H504 precision 下跌，应接受真实结果，不通过调 cooldown 找回旧分数。

这个点子的价值首先是**可信评价**，不是承诺提高 precision。

## IDEA-EML-08：Multi-horizon competing-risk landmark stack

### 动机

H504 最终目标跨度长，直接二分类会浪费中间过程信息；H10/H60 等短期信号又不能直接冒充 H504。可以让它们成为**辅助 hazard supervision**，最终评价仍固定在 H504 joint target。

### 设计

把每个 t 日候选转成多个 landmark interval，例如：

```text
(0,20], (20,60], (60,120], (120,252], (252,504]
```

每个区间预测 competing hazards：

```math
h_g(b|X_t)=P(goal\ in\ b\mid event\ free\ before\ b,X_t)
```

```math
h_r(b|X_t)=P(risk\ in\ b\mid event\ free\ before\ b,X_t)
```

再计算 504 日内 goal-before-risk 概率，而不是把 H10 +30% precision 当长期标签。

第一版不需要神经网络，可用低容量 Logistic / HGB 对 person-period rows 做离散时间 hazard；`horizon_bin`、market regime、KDJ/position mechanism score 作为输入。右删失样本只贡献其真实观察到的区间。

### 为什么值得试

- 利用早期 risk/goal 的时间信息，而不仅是 504 日终值；
- 允许近年的部分随访进入生存训练，不必把所有不足 H504 的候选直接删掉；
- 最终仍可输出用户真正关心的 `P(goal before risk by 504)`。

### 验收

同一 candidate ledger、同一 market calendar 下比较：

```text
direct H504 classifier
vs discrete-time goal/risk hazards
vs hazards + H10 OOF auxiliary score
```

主指标仍是 H504 event-level joint precision、event recall、校准、distinct stock/date、clustered CI。若 3/4 时间折不能稳定优于 direct baseline，或者增量只来自更宽松候选筛选，淘汰。

---

## IDEA-EML-09：Threshold-stability regularizer for publication budget

### 动机

当前 RF 四折 score 分布漂移很大，top-2%-fit threshold 在未来产生的 signal 数差异明显。与其只优化分类 loss，可把“发布预算稳定性”作为二阶段选择约束。

### 方案

不改基础模型训练，先在 temporal calibration 上对候选 policy 做稳定性选择：

```math
J = Precision_{LCB} - \lambda \cdot CV(signal\_share) - \gamma \cdot ECE
```

其中所有项只在 calibration folds 计算；outer test 完全冻结。`lambda/gamma` 不是先验最优值，只允许在 inner temporal folds 选择。

### 对照与淘汰

与纯 precision threshold、固定 top-rate、固定 absolute probability 三种 policy 同 test block 对比。若稳定性正则降低 signal-share CV，却牺牲 event recall 且没有提高 precision LCB，则淘汰，不为了“看起来稳定”牺牲有效事件覆盖。
