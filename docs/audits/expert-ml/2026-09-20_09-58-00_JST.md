## 0. 本轮结论

这轮不再重复“RSI专家0/100”本身，而是进一步纠正它的**归因**：

1. `rsi_mean_reversion` 的**总分**在 `cards_100` 上即使存在约 0.58 的练习集排序 AUC，也**不能被当成“连续 RSI 有效”的证据**。上一轮独立重算已经证明，只有 **3/100** 张卡的 `rsi_oversold` 非零；其余 **97/100** 完全为 0。因此，在 50 正 / 50 负的 2,500 个正负样本配对中，**至少 2,350 对（94.0%）两边的 RSI 超卖分量都为 0**，旧 RSI 分量最多只能在约 6% 的正负对上改变总分排序。总分的绝大多数排序来自回撤、下影/收盘位置、KDJ 和量能，而不是 RSI。
2. 上一轮重算给出的 `rsi_oversold mean=0.0037, max=0.1388` 进一步意味着其加权贡献 `0.30*rsi_oversold` 的均值约 **0.00111**、最大约 **0.04164**。因此“总专家分数有一点排序力”与“RSI有增量”是两个不同命题。
3. 当前 dense ML 矩阵的 82 个正式特征包含 KDJ，但**没有任何 RSI 列**；而 `src/ml/build_matrix.py` 文档写的是把专家机制重建成 raw continuous features。对 RSI 机制而言，这个覆盖承诺目前并未实现。因此现阶段准确说法不是“RSI已经被ML试过效果一般”，而是“RSI二值复合专家试过，但连续 RSI 尚未进入主 ML 矩阵”。
4. 下一步不继续堆 RSI 周期，而是把归因实验升级成 `RSI-ATTR-03`：先把旧复合专家拆成 **非RSI小计 vs RSI分量**，再比较 SMA-RSI、Wilder-RSI、fresh/roll-out 分解、ATR归一化价格承接，以及一个新的可选交互 **RSI Recovery Consensus, RRC**。
5. 本轮审计沙箱的 Python/container 启动仍返回 `ClientError`，所以没有冒充新增 pytest、HGB、MLP 或 H504 实股训练。当前真正的新增是固定 SHA 源码复核、归因算术和下一批实验合同；上一轮 07:26 的 `15 passed` 与 100-card 离线重算属于上一轮本地证据，不冒充本轮执行。

## 2. 新增研究归因问题：`EML-P1-RSI-ATTRIBUTION-CONFOUND`

**级别：P1（研究解释风险，不是当前实现崩溃）**  
**状态：新增确认**

### 2.1 证据

当前专家公式：

```text
score =
  0.30 * rsi_oversold
+ 0.25 * drawdown
+ 0.20 * rejection
+ 0.15 * kdj_turn
+ 0.10 * nonpanic_volume
```

上一轮独立离线重算的真实 100-card 统计：

```text
cards                         = 100
positive / negative           = 50 / 50
rsi14 <= 45                   = 3 / 100
rsi14 <= 25                   = 0 / 100
rsi_oversold mean             = 0.0037
rsi_oversold max              = 0.1388
expert raw score min/mean/max = 0.0354 / 0.2095 / 0.4926
binary fires at 0.68          = 0 / 100
```

因为 `rsi_oversold=0` 对 97 张卡成立，令三张非零卡中有 `p` 张正例，则 AUC 的 2,500 个正负配对中，两边 RSI 都为 0 的对数为：

```text
(50 - p) * (50 - (3 - p)), p in {0,1,2,3}
```

最小值是：

```text
47 * 50 = 2,350
```

即至少：

```text
2350 / 2500 = 94.0%
```

的 AUC 正负配对，旧 RSI 分量对两张卡完全相同（均为0），不可能改变两者排序。反过来，**最多约6%** 的正负配对有机会受到该 RSI 分量影响。

加权后：

```text
mean contribution ~= 0.30 * 0.0037 = 0.00111
max contribution  ~= 0.30 * 0.1388 = 0.04164
```

### 2.2 影响

因此：

- `rsi_mean_reversion` 总分的练习集 AUC（上一轮约0.58）主要是**复合规则其余四项**的排序，不能当“RSI连续分量有信号”的 null gate；
- `predicted_yes_count=0` 也不能证明 RSI 无效，因为硬阈值把所有连续排序都丢掉；
- 以后任何“RSI增量”必须把同一专家里的 `drawdown/rejection/kdj_turn/nonpanic_volume` 控制住，否则会把非 RSI 信息算到 RSI 名下。

### 2.3 验收

本地 agent 必须生成 `cards100_rsi_attribution.csv`，逐卡包含：

```text
sample_id, label,
rsi14, rsi_oversold,
drawdown, rejection, kdj_turn, nonpanic_volume,
score_non_rsi,
score_rsi_component,
score_total
```

并报告：

```text
AUC(score_non_rsi)
AUC(score_total)
AUC(rsi_oversold)
ΔAUC_total_vs_non_rsi
pairwise_activity_rate(rsi_oversold)
pairwise_rank_flip_rate(total vs non_rsi)
unique_values / zero_share / variance
```

练习集只做机制/归因 gate，不作市场收益或 H504 成绩。

## 4. 因子升级：从 RER 到 `RSI Recovery Consensus (RRC)`

上一轮 RER 使用 SMA-RSI 的 fresh contribution 与价格承接。它适合作为候选，但仍可能是在“修正 SMA 硬窗口滚出”而不是真正新增动量信息。

因此增加一个**对照型交互**：同时要求 SMA fresh contribution 与 Wilder RSI 都显示恢复。

### 4.1 原始向量必须保留

```text
rsi_sma14
rsi_wilder14
rsi_sma_delta3
rsi_wilder_delta3
rsi_fresh3
rsi_rollout3
rsi_fresh_positive_share
rsi_rollout_dominant
support_break_log
support_break_atr
abs_move14
```

其中 `fresh/rollout` 只适用于固定窗口 SMA 分解；Wilder 递推版不能套同一个“硬滚出”定义。

### 4.2 RRC 可选交互

定义：

```text
F3 = 最近3日 SMA-RSI fresh contribution 总和
W3 = Wilder RSI14 的3日变化
B  = support_break_atr >= 0
```

正部平滑：

```text
pos_tanh(x; s) = tanh(max(x, 0) / s)
```

首轮预注册尺度：`s_F = s_W = 5 RSI points`。

候选交互：

```text
RRC = sqrt(
        pos_tanh(F3; 5)
        * pos_tanh(W3; 5)
      ) * exp(-B)
```

解释：

- 纯 SMA 滚出、没有新增恢复：`F3<=0` → RRC=0；
- SMA fresh 和 Wilder 都转强，且低点承接尚可 → RRC提高；
- RSI已经长期100、近期没有“恢复事件” → RRC可以为0，这**不表示看空**，因此必须同时保留 RSI 水位和趋势特征；
- RRC 是交互特征，不是概率，不作为硬发布门槛。

### 4.3 淘汰条件

如果在同候选、同标签、同时间块下：

```text
B + KDJ + Wilder level/delta + raw returns
```

已经达到与加入 `fresh/rollout/RRC` 相同的开发表现，且后者没有稳定的配对 log-loss / Brier / 排序增量，则 RRC 记为 `COMPLETE_NEGATIVE`，不继续堆更多 RSI 交互。

## 5. `RSI-ATTR-03` 的同条件矩阵

### 5.1 练习卡：只回答归因，不回答市场有效性

```text
C0 = non-RSI subtotal
C1 = old rsi_oversold only
C2 = total old expert score
C3 = raw RSI14 / delta3
C4 = SMA fresh/rollout vector
C5 = Wilder level/delta
C6 = C4 + support_break_atr + RRC
```

必须报告 `activity rate` 与 `rank flip rate`，避免一个几乎全常数的特征靠少数样本制造虚假的“有AUC”。

### 5.2 真实历史机制诊断（即使H504正式OOS受阻也能做）

在完整真实历史上统计：

```text
A: sma_delta3 > 0
B: fresh3 > 0
C: wilder_delta3 > 0
D: support_break_atr <= 1
```

重点四类：

```text
rollout_only      = A and not B
sma_wilder_split  = A and not C
fresh_consensus   = A and B and C
supported_recover = A and B and C and D
```

按 year / KDJ zone / long position / ATR / liquidity / history length 分层，输出样本数与比例。这里不需要未来标签，因此可以在 `BLOCKED_DATA` 的正式H504状态下继续推进。

### 5.3 合法 H504 时间折存在后才做模型增量

共同基础 `B0` 必须明确排除 RSI/KDJ 派生及结果字段，并包含共同价格承接信息，避免把 Low/ATR 新信息归给 RSI。

```text
M0 B0
M1 B0 + KDJ
M2 B0 + KDJ + non-RSI expert raw components
M3 M2 + SMA RSI level/delta
M4 M2 + Wilder RSI level/delta
M5 M2 + SMA + Wilder
M6 M5 + fresh/rollout vector
M7 M6 + RRC
M8 raw-delta control: M2 + equivalent 14日价格变化摘要（无RSI）
M9 M8 + RSI vector
```

主要问题：

```text
M3 - M2  : SMA RSI 在已有 KDJ/非RSI机制后是否有增量？
M4 - M2  : Wilder 是否更稳？
M6 - M5  : fresh/rollout 分解是否超出两类 RSI 本身？
M7 - M6  : RRC 交互是否有价值？
M9 - M8  : RSI 是新增信息，还是对同历史的更好表达？
```

调参、校准、policy 和最终测试继续分开。
