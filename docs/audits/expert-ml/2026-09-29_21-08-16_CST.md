## 1. 实时源码证据

当前 `registry.py`：

```python
def latest_complete(self,signature):
    for r in reversed(self.rows()):
        if r.get('signature')==signature and str(r.get('status','')).startswith('COMPLETE'):
            return r
    return None
```

这里没有任何 artifact 检查。

`run.py` 的 H504 路径：

```python
previous=registry.latest_complete(sig)
if previous is None:
    r=run_h504_hgb(...)
    registry.append(...)
else:
    results.append({
        'status':'REUSED_COMPLETE',
        ...
    })
```

AUX 也是相同模式。

因此：

```text
registry COMPLETE 行
```

本身就足以阻止重新训练。

## 3. AUX 同样存在 status-only reuse

`run_aux_tcn()` 虽然返回：

因此路径存在于旧 JSON 不等于文件今天仍然完好。


status-only registry 无法识别这些情况。

## 7. 窄产品修复

在一个实验被写成 COMPLETE **之前**，先生成不可变 artifact manifest：

```text
artifact_manifest_schema
role
relative_path
byte_size
sha256
```

H504 至少要求：

```text
model
dev_predictions
metrics
```

AUX 至少要求：

```text
best_checkpoint
dev_predictions
metrics
```

建议同时记录：

```text
last_checkpoint
train_history
```

作为 resumability evidence，但它们是否属于 COMPLETE 的硬 required role 可以单独定义。

只有：

```text
模型 reload 验证通过
best model 重新生成完整 dev predictions
required artifacts 都存在
hash 已计算
```

之后，才能 append `COMPLETE_*` registry row。

## 8. reuse 时必须重新验 artifact，而不是只验文字状态

建议：

```text
signature match
→ task_scope/evidence_type match
→ artifact manifest schema match
→ required roles complete
→ re-hash every required artifact
→ hash/size match
→ REUSED_COMPLETE
```

否则状态应是：

```text
LEGACY_UNCERTIFIED_ARTIFACTS
ARTIFACT_MISSING
ARTIFACT_HASH_MISMATCH
```

不能直接 reuse。

旧 registry status-only COMPLETE 不应该自动升级成新 schema 的认证 COMPLETE。

## 9. 与 pipeline identity / fit budget 的关系

前几轮已确认：

```text
pipeline identity 可能漏依赖
48-fit 需要 persistent RESERVE
```

artifact attestation 是第三层：

```text
experiment identity
→ artifact attestation
→ duplicate COMPLETE reuse decision
→ 如果不可复用且需要重训
→ persistent fit RESERVE
→ actual fit
```

不能因为 artifact 缺失就直接无预算重训；也不能因为 registry 写过 COMPLETE 就拒绝重训。

```text

```

模型可复用与“三小时 session 完成”仍是两件不同的事。
