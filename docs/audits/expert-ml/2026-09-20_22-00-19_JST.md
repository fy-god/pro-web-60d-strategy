## 0. 本轮结论

这轮不继续增加 RSI 阈值，也不继续把 36 个 expert hard-vote 当作 36 份独立信息。优先新增一个与现有“量压”不同的可证伪候选：**VIR（Volume-Impact Recovery，量价冲击恢复）**。

它回答的问题是：

> 在相同上涨/下跌成交量结构下，近期价格是否变得“上涨时对成交量更敏感、下跌时对成交量更迟钝”？如果这种方向性价格冲击改善发生在 KDJ 低区/恢复阶段，它是否能补充单纯的 `P_w=(D_w-U_w)/(D_w+U_w)` 量压？

VIR 只是成交量—价格响应的统计代理，不称“机构吸筹”“主力承接”。首轮必须把原始上涨冲击、下跌冲击、计数、coverage 和 one-sided 状态全部交给模型；VIR 合成量只用于测试有限容量模型是否受益，不能硬门控发布。

## 3. 新优先因子：VIR（Volume-Impact Recovery）

### 3.1 为什么不是再做一个量压阈值

用户已经冻结的量压起点为：

\[
P_w=\frac{D_w-U_w}{D_w+U_w},
\]

其中 `D_w/U_w` 是下跌/上涨日的历史成交量总和。它回答“成交量更多出现在跌日还是涨日”，但不回答“同样一份成交量推动了多大价格变化”。

仓库 `src/ml/build_matrix.py` 当前 volume 组主要是均量、量比和稳定性；`experts/features.py` 有 `positive_volume_share`，也仍然只按涨跌日统计量。`src/lowzone.py` 的旧 `down_vol_ratio5` 还存在互斥 5 日窗口各自 `min_periods=3` 的已知定义问题。

所以本轮不再复制成交量方向占比，而研究**价格对方向成交量的冲击效率是否改变**。

### 3.2 日级输入

对每个股票市场 session `s`：

\[
r_s=\log(C_s/C_{s-1}).
\]

波动尺度只使用前一 session 已知信息：

\[
a_s=ATR14_{s-1}/C_{s-1}.
\]

成交量基准同样冻结在当前 session 之前：

\[
\bar V_s=mean(V_{s-20},\ldots,V_{s-1}),\qquad
q_s=V_s/\bar V_s.
\]

标准化价格变化：

\[
z_s=r_s/(a_s+\epsilon).
\]

要求：

- `ATR14` 与 `VMA20` 不使用当日自身作分母，避免当前冲击把自己的尺度同步放大；
- 股票缺市场 session 时，不把缺口两端当成连续一天；独立 market calendar 上缺失保持 mask；
- `a_s<=0`、`VMA20<=0`、未知价格或未知 volume 时该日 contribution 为 unknown，不伪 0。

### 3.3 一个 10-session block 的方向冲击

\[
I^+ =
\frac{\sum (z_s)_+}
     {\sum q_s\,1[z_s>0]},
\qquad
I^- =
\frac{\sum (-z_s)_+}
     {\sum q_s\,1[z_s<0]}.
\]

同时保存：

- `n_up`
- `n_down`
- `n_flat`
- `coverage`
- `up_rel_volume_sum`
- `down_rel_volume_sum`
- `impact_up`
- `impact_down`
- `one_sided`

首轮 block 只有在 `n_up>=2` 且 `n_down>=2`、两边分母均有效时才定义双边 asymmetry；否则 `asymmetry=NaN` 并由 validity/mask 告诉模型为什么缺失。

方向冲击不对称：

\[
A=\log\frac{I^++\epsilon}{I^-+\epsilon}.
\]

### 3.4 VIR：最近 10 日 vs 前一个 10 日

不用嵌套 10/20 窗口，首轮采用两个**不重叠** block：

- `prior10 = t-19 ... t-10`
- `recent10 = t-9 ... t`

定义：

\[
\boxed{VIR_t=A_{recent10}-A_{prior10}}.
\]

VIR 高表示：相对前一个 10-session block，近期上涨方向的单位相对成交量价格冲击变强，和/或下跌方向单位相对成交量冲击变弱。

它不区分哪一部分主导，因此原始 `I^+ / I^- / A` 必须全部保存；不能只给模型一个 VIR。

### 3.5 与量压不同的构造反例

固定每边相对成交量总和都为 2，故两段的量压都为 0。

假设 ATR 价格尺度均为 2%。

**prior block**：两次上涨各 +1%，两次下跌各 -1%。

- 每次标准化绝对变化 = 0.5
- `I+ = 1/2 = 0.5`
- `I- = 1/2 = 0.5`
- `A_prior = log(1)=0`

**recent block**：上涨两次各 +2%，下跌仍各 -1%，成交量结构完全不变。

- `I+ = 2/2 = 1.0`
- `I- = 1/2 = 0.5`
- `A_recent = log(2)=0.6931`
- `VIR = 0.6931`

量压完全一样，但价格响应不同。这个反例说明 VIR 至少在定义上不是 `P_w` 的代数重命名。

首轮还必须做以下反例：

1. 价格整体乘 10：VIR 不变；
2. volume 整体乘 10，同时历史量基准同比缩放：VIR 不变；
3. 只修改 `t+1...`：截至 `t` 的 VIR bit-identical；
4. recent block 全涨或全跌：双边 VIR = unknown，不准变成极大分数；
5. 同一个 `P_w`、同 `n_up/n_down`、同 volume sums，改变价格响应：VIR 必须变化；
6. 同价格路径、随机打乱 block 内 volume：检查 VIR 是否主要来自价格而非量；这个是诊断，不能拿随机结果作真实因子结论；
7. 中间缺一个 market session：不能把两侧观测压缩成连续 10 日。

## 5. 两个备选探索与淘汰条件

### 5.1 备选 A：MCDR（Market-Conditioned Downside Resilience）

`src/ml/build_matrix.py` 已经有 `mkt_ret1`、`beta_60`、`resid_ret1`，但只有单日残差，没有“市场下跌时个股是否越来越抗跌”的历史摘要。

首轮定义：

\[
e_s=r_{stock,s}-\beta_{s-1}r_{market,s},
\]

注意 beta 使用 `s-1` 冻结值。只在 `market_ret_s<0` 的日期统计：

- `down_mkt_resid_mean20`
- `down_mkt_resid_positive_rate20`
- `down_mkt_resid_q25_60`
- `down_mkt_n20/60`
- `down_mkt_resilience_change = recent20 - prior40`

不足 5 个 market-down 观测时设 unknown。

淘汰：加入 `resid_ret1` 历史原始窗口、market return、beta 与 position 后，两个开发块的 paired log-loss/Brier/AUC/发布指标方向不一致或近似 0，则停止，不再加周期。

### 5.2 备选 B：family effective breadth

沿 MEB 家族去重思想，不增加新的“专家”。对训练块冻结后的 family activation `a_f`：

\[
N_{eff}=\frac{(\sum_f a_f)^2}{\sum_f a_f^2+\epsilon}.
\]

同时保存有效 family 数，使用 `N_eff / n_valid_family` 做归一化。它只描述“支持是否来自多个独立机制”，不能当概率。

淘汰：若在 family-q vector 已进模型后 `N_eff` 在两个开发块都无配对增量，则直接记 `COMPLETE_NEGATIVE`。

本轮只有一个优先实验 VIR；MCDR 与 effective breadth 是两个备选，不同时把三条都扩成大扫参。

- 禁止 `sleep`、重复同 hash fit、无意义扩大 epoch/seed 或重做相同缓存来凑 60 分钟；
- 若数据/协议/环境让**所有** READY 包都阻塞，可提前退出，但必须记 `MIN_RUNTIME_NOT_MET` 与具体 `BLOCKED_*`；
- 单次仍不得超过 75 分钟研究预算，给 90 分钟 launcher 留交接/提交余量；
- 整批累计不得超过用户 v2 的 `180 wall-minutes / 48 fits`。

### 6.2 三个连续 slice，把 180 分钟上限真正排满

#### Slice A：协议＋真实全量因子工程（目标 60—75 有效分钟）

优先顺序：

1. 保存 HEAD/dirty/environment/资源；读取已有 registry/checkpoint，若不存在则初始化；
2. 盘点 `PWS_DATA_ROOT` 下所有授权行情而不是只读 `SOURCES` 两个文件，输出完整 `data_inventory.json`；
3. 构造独立 market calendar，重做 `entry_session/deadline/known_at` 合同与 `fold_support.json`；
4. 在全量真实 panel 上实现并缓存 pressure/KDJ-path/VIR；
5. 跑 feature health：coverage、NaN/inf、one-sided、分位、年份、position、KDJ、流动性、gap 长度分层；
6. 做 VIR 的 price-only / same-pressure counterfactual / scale / prefix / gap 测试；
7. 如果仍未满 60 分钟且上述工作已完成，继续 MCDR 的数据健康实现或创建 prospective ledger；不得退出去等下一轮。

#### Slice B：表格训练与消融（目标 60—75 有效分钟）

存在合法 H504 dev fold 时，seed=17 依次 M1/M2/M2P/M2K/M2I/M2PI/M3/M3I/C-RAW/C-NOVOL；每次保存全候选预测、模型 hash、reload 一致性、时间/内存。

如果 H504 fold 因历史长度阻塞：

- **禁止缩短 H504**；
- 继续真实 panel 因子诊断、prospective unknown scoring、FeatureSpec/ledger；
- H10 只能作为“实现方向 smoke/legacy mechanism diagnostic”，单独命名，不得写 H504 成绩；
- 可运行 past-only 自监督 sequence 预训练，但输出必须标 `PRETRAIN_ONLY_NOT_H504_RESULT`。

#### Slice C：NN＋错误分析＋一次再训练（使用剩余累计预算，最多到 180 分钟）

1. 少量样本 overfit、gradient、mask、prefix causality；
2. 合法 dev 上 M4a/M4b，再按表格证据决定 M5a/M5b；
3. 形成高置信 FP/FN、risk/timeout/no-entry/unknown 错误切片；
4. 按 year、stock cluster、liquidity、history length、market regime、VIR validity 分层；
5. 只挑一个有样本支持的机制改动，做一次 paired retrain；
6. 保存 best/last、optimizer/random state、完整预测、next_actions 与精确 resume 命令。
