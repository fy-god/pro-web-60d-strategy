## §2 【已确认错误 · P1】`PT2H30M`(9000s) 低于 10800s 目标

**文件/行**：
- `scripts/register_fixup_task.ps1:96` `$timeLimit = "PT2H30M"` → `:115` 注入 `<ExecutionTimeLimit>`
- `scripts/run_fixup.task.xml:16` `<ExecutionTimeLimit>PT2H30M</ExecutionTimeLimit>`
  （blob `363a57e44aa6…`，2822 B，**UTF-16LE BOM `FF FE`**——用 UTF-8 读会看起来是空文件）

**触发条件/反例**：单纯算术，不依赖任何外部状态。

```
PT2H30M = 2*3600 + 30*60 = 9000 s
target_active_seconds    = 10800 s   (receipts.py:55)
normal_wall_limit        = 12600 s   (receipts.py:56)
AGENT_TIMEOUT_SECONDS    = 13200 s   (scripts/run_fixup.py:23)
```

**机制**：Windows 在 `ExecutionTimeLimit` 处**杀掉进程**。9000 s < 10800 s ⇒
`ResearchSessionReceipt.finalize()`（`receipts.py:154`）的
`'target_met': effective >= self.target_active_seconds`（`:173`）
在**该任务定义下恒为 `False`**——`effective` 是各阶段 `elapsed_seconds` 之和，被 9000 s 硬封顶。
且链序应当单调（注册上限 > runner > normal wall > 目标），实际为 **倒置**。

**影响**：任何按跟踪模板注册的机器，其本机研究**永远**只能产出 `target_met=false` 的收据；
叠加 §3 的「退出码不看收据」，运维侧看到的是**绿灯 + 永远未达标**，无任何自愈信号。

**修复建议**（沿用前轮建议值，并补齐链序）：把注册上限改为 `PT3H50M` = **13800 s**
（> runner 13200 > normal wall 12600 > 目标 10800），`scripts/run_fixup.task.xml` 与
`scripts/register_fixup_task.ps1:96` **同一值**；并删除 `:102` 那句过期注释（"90 minutes / 5400s"）。
**注意**：按 v5，**不得**用 delete/create 重建任务，只窄改既有任务的 `ExecutionTimeLimit`。

**验收测试**：新增断言 `parse_duration(ps1 的 $timeLimit) == parse_duration(task.xml 的 ExecutionTimeLimit)`
且 `>= AGENT_TIMEOUT_SECONDS >= target_active_seconds`；变异任一值 ⇒ 必须失败。
