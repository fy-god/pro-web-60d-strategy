### 2.3 机制（含我做的**判别性阳性/阴性对照**）

`git rebase --autostash` 的 `--autostash` **只保护"已跟踪文件的未提交修改"**（即 `git stash` 能纳入的东西）；它**不覆盖未跟踪路径**。当 `origin/main` 新增了一个路径、而工作树里该路径正以**未跟踪**状态存在且内容不同，`rebase` 需要 checkout 该路径时会被 git 拒绝。

**判别性对照（单变量，仓外沙箱，与 `commit_and_push()` 命令序列一致）**：

```text
POSITIVE（工作树存在未跟踪 docs/peer.md）：rebase rc=1
    error: The following untracked working tree files would be overwritten by checkout:
    	docs/peer.md
    Please move or remove them before you switch branches.
    Aborting
NEGATIVE（不放该未跟踪文件）        ：rebase rc=0
    Rebasing (1/1)
    Successfully rebased and updated refs/heads/main.
DISCRIMINATING = True
```

两臂**只差这一个变量**：远端那一笔**只新增 `docs/peer.md`、不碰 `AUDIT_STATUS.md`**。必须这样做——我第一版对照让远端**也改** `AUDIT_STATUS.md`，结果**阴性臂以内容冲突（`CONFLICT (content)`）失败**，那是**另一种**失败原因，对照**失去判别力**；我作废并重做。（同样作废的还有更早一版：我在 push 之后才克隆 worker，`docs/peer.md` 在副本里**已经是跟踪文件**，于是 `--autostash` 正常处理、rebase 成功——探针**根本没走到被测分支**。）

⇒ **脚本自己的 docstring「the rebase cannot conflict」被实测推翻**：冲突源不是它 commit 的那个文件，而是**另一条自动化（本审计线）留下的未跟踪报告文件**。两条自动化的文件集互不重叠，但 git 的 checkout 守卫看的是**路径**，不是"谁提交的"。
