## 0. 本轮结论

ARR-02 已经在合成压力/训练中得到“没有一致增量”的负结果，下一步不应继续围绕同一个乘积公式扫阈值。本轮把瓶颈转向**专家信息怎样无重复地融入ML**。

当前专家库共有36个策略，但“36个策略”不等于36份独立信息。至少两类证据已经足够明确：

1. `strict_*` 中存在只复用同一个 base raw score、仅更换阈值的选择器。`strict_relative_strength` 与 `strict_relative_strength_v2` 都复用 `relative_strength_rank`；`strict_obv_volume_price` 与其v2都复用 `obv_volume_price`。`_strict_selector.thresholded_decision()`明确返回 `base.score` 和 `base.components`，只改变二值阈值。
2. 真实 `cards_100/scores.json` 的100-card练习归档中，`accumulation_base / first_board_breakout / high_level_consensus / reversal_engulf / rsi_mean_reversion / turnover_weak_to_strong` 六个策略都是 `predicted_yes_count=0`。也就是说，若直接平均36个二值票，至少6/36=16.7%的票在这个benchmark上是恒定0，不携带样本排序信息。

因此新增候选不是“第37个固定规则”，而是一个**机制家族去重广度特征 MEB（Mechanism-Equalized Breadth）**：每个真实机制家族只保留一个base raw score，用训练块内的经验分位归一化后计算独立家族支持广度，并把家族原始向量、广度、集中度和coverage一起交给模型。strict阈值克隆仍可作为发布政策/诊断，但不能冒充独立专家输入第二层。

这是一项融合假设，不是市场收益结论。当前仓库主ML矩阵本身主要重建raw continuous features，并未发现已经把36个专家hard votes直接作为正式82列输入；因此本轮把“克隆重复”标为**未来融合的确认风险**，不错误宣称现有H10矩阵已经发生该bug。

## 2. 新证据：专家数量正在高估独立信息数量

### EML-P1R-FAMILY-THRESHOLD-CLONE-OVERCOUNT【P1风险，融合前必须处理】

**证据。** `_strict_selector.thresholded_decision()`执行 `base = base_predict(card)` 后，把 `base.score`、`base.components` 原样复制，仅把 `prediction=int(base.score >= threshold)` 改成严格阈值。`strict_relative_strength` 和 `strict_relative_strength_v2` 的 `BASE_STRATEGY_ID` 都是 `relative_strength_rank`；OBV两条strict变体同理。

100-card归档进一步给出：

- `relative_strength_rank` 发布45/100；`strict_relative_strength` 9/100；`strict_relative_strength_v2` 11/100，两个strict版本二值disagreement只有0.02。
- `obv_volume_price` 发布64/100；`strict_obv_volume_price` 9/100；`strict_obv_volume_price_v2` 10/100，两个strict版本disagreement只有0.01。

这不是“三个专家独立同意”，而是**同一个连续分数被切了三个阈值**。若未来meta把base+strict+strict_v2当三列独立expert score，raw-score列甚至是完全重复；若用二值票，则是一条标量的三个阶梯函数，同一机制获得三次权重机会。

**修改原则。** 新增显式 `family_id/base_strategy_id/is_threshold_clone`；第二层默认只消费base raw score和raw components。threshold clone只保存为policy diagnostic，不进入independent-family计数。回归测试：把同一base score克隆5个阈值版本，MEB/family vector必须bit-identical；naive hard-vote count允许变化，用于证明旧方法的克隆敏感性。

### EML-P2-CARDS-HARDVOTE-DEGENERACY【P2，真实benchmark确认】

100-card平衡练习集里以下六个策略 `predicted_yes_count=0`：`accumulation_base`、`first_board_breakout`、`high_level_consensus`、`reversal_engulf`、`rsi_mean_reversion`、`turnover_weak_to_strong`。六列恒定0占36策略的16.7%。

这不能证明这些机制在真实H504全市场永远无用；但它证明“专家数量=信息量”的假设在机器归档上不成立。若简单 `mean(hard_vote)`，恒0列会机械压低所有样本共识，且不给排序提供任何信息。融合应优先raw score/component，再用训练块中的分布做归一化。

## 3. 新候选因子：MEB（Mechanism-Equalized Breadth）

目标不是替代KDJ/位置/ARR，而是描述：**有多少互不重复的机制家族，同时把当前候选排在各自历史训练分布的高位。**

### 3.1 family定义

对策略e：

- 有 `BASE_STRATEGY_ID` 且只是 `thresholded_decision` 包装：`family_id = BASE_STRATEGY_ID`，`is_threshold_clone=true`。
- base策略：`family_id = strategy_id`。
- 真正改变raw公式/输入的信息增量版本，只有在静态源码+数值对照证明不只是阈值变化后才能成为新family。

family映射必须版本化并进入feature hash。

### 3.2 训练块内归一化

只在训练块拟合每个family base raw score的经验CDF：

`q_f(t) = F_train,f(s_f(t))`

开发/校准/测试只调用冻结的训练ECDF映射，不在目标块重新排名。缺失保留mask，不能填0。

soft support：

`a_f(t) = sigmoid((q_f(t) - 0.75) / 0.10)`

0.75和0.10是首轮固定起点，不是最优参数；不在最终测试调。

机制等权广度：

`MEB(t) = mean_f a_f(t)`

同时输出：

- `family_support_count_75 = sum(q_f >= 0.75)`
- `family_support_count_90 = sum(q_f >= 0.90)`
- `family_coverage = finite_family_count / configured_family_count`
- `family_dominance = max(a_f) / (sum(a_f)+eps)`
- 每个 `family_q_*` 原始分位向量

MEB不是概率，也不是“票数越多必涨”。dominance高表示可能只是单一机制尖峰；coverage不足单独报告。

### 3.3 为什么不直接平均36个分数

不同专家raw score的尺度和饱和区不同；strict clone又完全复用base score。训练块ECDF先解决跨家族尺度问题，family去重再解决阈值克隆问题。之后模型同时看到family vector和MEB，让模型决定“广泛支持”和“少数强机制”哪个更重要。

## 4. 融合到H504主线的具体方式

不修改用户主任务：A股、t收盘、下一市场日有效Open=E、504市场日Close严格>4E、此前含达标日Low>=0.8E、同日risk优先、t+1无Open不顺延。

建议新模块（当前远端不存在，均标待新增）：

- `experts/families.py`：family registry、base/clone验证。
- `src/ml/research_h504/expert_family_features.py`：运行base expert raw score/components，拟合/应用train-only ECDF，输出family vector/MEB。
- `src/ml/research_h504/feature_spec.py`：显式白名单，禁止known_at/deadline/label/outcome/execution进入X。
- `tests/research_h504/test_expert_families.py`：克隆不变性、family coverage、train-only ECDF。
- `tests/research_h504/test_meb.py`：缺失、常数score、重复clone、未来块重新排名禁止。

融合顺序：快照/路径/压力基线 → `+ family_q_vector` → `+ MEB/count/dominance` → OOF meta。严格阈值票只作诊断列，不作为独立family特征。

## 8. 验收与淘汰条件

MEB继续研究的最低条件：

- family映射经源码与数值测试确认，threshold clone复制不改变family特征；
- train-only ECDF无时间泄漏，dev/test不重新拟合分位；
- F3/F4/F5使用完全相同candidate/label/split/policy；
- 至少一个独立开发块上F4或F5相对F0/F3改善log-loss/Brier或预注册发布指标，同时信号/Recall没有灾难性缩水；
- 第二开发块方向不反转，或明确给出不稳定结论。

若family raw vector已经吸收全部信息，MEB摘要无增量，则保留family向量、淘汰MEB交互；若去clone本身不改善模型，不代表clone可以恢复为独立专家——raw完全重复仍属于表示冗余。若100-card表现好但H504开发无增量，只保留为练习集诊断结果。
