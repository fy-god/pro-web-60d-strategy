## 3. 本轮真正推进：候选 v4 修掉长运行最关键的两类恢复缺陷

上一版v3已经有 `--stage all`、H504候选fail-closed、AUX-TCN、JSONL registry和完整dev prediction，但对用户要求的**单次连续三小时**仍有两个执行可靠性缺口：

### 3.1 `EML-CAND-P1-BEST-OPTIMIZER-MISMATCH`：v3 best checkpoint并非同一训练时刻

v3 的 `run_aux_tcn()` 在训练结束后先把模型权重回滚到 `best_state`，随后保存：

```python
model.load_state_dict(best_state)
torch.save({
    'model': model.state_dict(),
    'optimizer': opt.state_dict(),
    ...
}, out_dir / 'best.pt')
```

问题是 `opt.state_dict()` 仍来自**最后训练epoch**，而 `model.state_dict()` 已是**最佳epoch**。所以 `best.pt` 不能被称为“精确可恢复的best训练状态”；在三小时任务被中断后若基于它继续优化，模型参数与AdamW一阶/二阶矩并不同步。

v4的修复：

- 每次dev改善时同时深拷贝 `best_model_state` 与 `best_optimizer_state`；
- `best.pt` 的model/optimizer必须来自同一个 `best_epoch`；
- `last.pt` 单独保存最后已完成训练状态，不再混用best与last语义。

### 3.2 `EML-CAND-P1-MIDFIT-NO-EXACT-RESUME`：v3 registry只能跨完整fit续跑

v3 registry可以跳过已完成的模型signature，但一个正在训练的TCN若被外层时限打断，训练函数本身没有epoch级 `last.pt`。这对于三小时窗口并不够：长fit被杀后仍可能从epoch0重做。

v4新增：

- 每个epoch后写 `last.pt`；
- wall budget在训练batch/epoch边界检查；
- 中断返回 `INTERRUPTED_BUDGET`，保留可恢复checkpoint；
- 保存optimizer、early-stop wait、history、DataLoader generator、Torch RNG、NumPy RNG、Python RNG；
- compatible rerun从 `last.pt` 继续，而不是从epoch0重新训练；
- checkpoint写入训练配置hash，batch size / LR / weight decay / patience / feature set / seed / window变化时返回 `BLOCKED_CHECKPOINT_MISMATCH`，禁止把旧checkpoint静默接到新实验。

`max_epochs`被视为可延长的训练预算而不是模型优化器身份；真正影响优化轨迹的配置进入hash。registry仍保留失败/中断attempt，只有 `COMPLETE*` signature可被跳过。

## 4. v4新增执行收据：不再把“配置了三小时”当“真的跑了三小时”

新增 `src/ml/research_h504/receipts.py` 候选模块，`--stage all` 会在重计算之前写：

- `local_start_receipt.json`
- `session_progress.json`
- `execution_receipt.json`

start receipt记录：session id、PID、Python/平台、source SHA、effective prompt hash、已注册任务timeout、10800秒目标、12600秒正常wall上限、13200秒runner硬兜底、evidence type和实际argv。

execution receipt记录实际wall与phase并集、fit started/completed/interrupted、数据计算秒、真实训练秒、synthetic训练秒、分析秒、idle类秒、stop reason、target是否达到，以及输出目录的重要JSON/CSV/checkpoint的SHA-256。

关键约束：

- `target_active_seconds=10800` 是目标，不是测量值；
- receipt不会因为配置了13200秒timeout就声称跑了13200秒；
- `evidence_type=SYNTHETIC` 时训练时间只能进入 `synthetic_train_seconds`，`real_train_seconds` 必须为0；
- 不把Git/Markdown/LLM等待算入有效研究时长。

这解决的是本项目此前反复出现的“任务书已经写了，但没有本机三小时证据”问题。
