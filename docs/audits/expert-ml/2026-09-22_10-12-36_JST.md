## 3. 新增 P1：registry 完成态与真实产物脱钩

### 3.1 源码事实

`src/ml/research_h504/registry.py` 当前实现：

```python
def latest_complete(self,signature):
    for r in reversed(self.rows()):
        if r.get('signature')==signature and str(r.get('status','')).startswith('COMPLETE'):
            return r
    return None
```

这里没有任何 artifact path、存在性、文件大小或 SHA-256 检查。

`src/ml/research_h504/run.py` 的 `all` 阶段会为 H504 T0 生成 signature，然后调用：

```python
previous = registry.latest_complete(sig)
```

只要返回非空，就直接追加：

```python
status = 'REUSED_COMPLETE'
```

并跳过 `run_h504_hgb(...)`。AUX TCN 分支采用同样的完成态复用逻辑。

而 `src/ml/research_h504/train_h504.py::run_h504_hgb()` 成功时虽然真实写出：

- `h504_T0/model.pkl`
- `h504_T0/dev_predictions.csv`
- `h504_T0/metrics.json`

但返回的 `metrics` 只包含指标、样本支持、模型参数和 split 信息，没有把上述关键文件的 `path + sha256` 纳入完成记录。随后 `run.py` 将 `**r` 写入 experiment registry，因此 registry 并不具备独立验证完成证据的材料。

### 3.2 可触发条件

只需要满足以下任意一种情况：

1. 上一轮完成后用户手工清理了 checkpoint/prediction；
2. 磁盘清理脚本删除部分大文件但保留 `experiment_registry.jsonl`；
3. 同目录文件被覆盖或截断；
4. 从另一机器只同步 registry，没有同步模型/预测；
5. checkpoint/prediction 损坏但文件名仍存在。

下一轮 signature 不变时，当前实现仍会进入 `REUSED_COMPLETE`。

### 3.3 为什么这是 P1 而不是普通可观测性问题

这不是“少打印一个路径”。它会改变研究控制流：旧结果被视为已完成后，训练被**直接跳过**。因此可能导致：

- 没有模型/完整预测却被统计为已完成；
- 三小时队列提前耗尽，出现伪 `all valuable work complete`；
- H504/AUX 对比无法由原始预测重新计算；
- 后续误差分析、校准和复验无法证明引用的是同一份模型；
- registry 与 receipt 形成“相互引用但没有底层证据”的假闭环。

它不会凭空提高市场命中率，所以不是“标签泄漏”类 P0；但它会使研究完成状态不可审计，因此列为 P1。

## 4. 沙箱反例与候选 guard

本轮在隔离目录复现当前 `latest_complete` 的语义，并写了 fail-closed artifact guard。测试全部使用临时文件，不接触真实市场数据、不修改仓库源码。

### 反例 A：完成行存在，真实文件不存在

构造 `COMPLETE_H504_DEV` registry 行，并登记不存在的 `model.pkl / dev_predictions.csv`。当前逻辑：

- `latest_complete(signature)`：**返回该完成行**；
- 因此当前 runner 会允许进入 `REUSED_COMPLETE`。

候选 guard：

- 要求每个 task scope 定义 required artifacts；
- 每个 artifact 必须具有 `path + sha256`；
- 文件不存在时拒绝复用，原因 `missing artifact file`。

### 对照 B：产物存在且 hash 一致

写入模型与预测文件并记录真实 SHA-256，guard 正常允许复用。

## 5. 最小修复方案

本轮按权限**不远端修改产品源码**。给本地实施者的窄修复顺序如下：

1. **完成时先落 artifact manifest。** H504 至少记录 `model.pkl`、完整 `dev_predictions.csv`、`metrics.json`；AUX 至少记录 `best.pt`、`last.pt`（如适用）、完整 dev predictions、train history。每项保存 path、bytes、sha256。
2. **registry 完成行必须携带 manifest。** 只有真实文件原子写完并算完 hash 后，才能追加 `COMPLETE_*`。
3. **复用改为 fail-closed。** `latest_complete_validated(signature, task_scope)` 只返回 artifact 全部存在且 hash 相等的完成行。
4. **坏完成行显式留痕。** 建议追加 `STALE_COMPLETE_ARTIFACT` 或 `BLOCKED_ARTIFACT_MISMATCH`，不能静默跳过。
5. **重跑仍扣 fit 预算。** 当旧完成证据失效而重新训练时，必须纳入尚未修复的全局48-fit累计预算；不能因为“这次只是补文件”绕过预算。
6. **receipt 引用同一 manifest。** execution receipt 应保存最终采用的 experiment signature 与 artifact manifest hash，做到 `receipt -> registry row -> artifact hash -> concrete bytes` 可闭环重算。

### 必要回归测试

- complete row + model missing → 不得 reuse；
- complete row + predictions missing → 不得 reuse；
- artifact bytes changed → 不得 reuse；
- intact paths + hashes → 允许 reuse；
- `metrics.json` 在、完整 prediction 不在 → 不得把指标文件当作完整市场证据；
- H504 与 AUX 使用各自 required-artifact schema；
- stale row 后新 fit 成功 → registry 保留旧 stale 记录和新 complete，不覆盖历史。

回滚很简单：候选 guard 只改变“是否允许复用完成行”，不改变候选定义、H504标签、特征或模型数学。若 guard 误判，回滚该验证层即可，不需要重写历史行情或标签。
