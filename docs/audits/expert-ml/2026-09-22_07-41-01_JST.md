### P2（`待验证风险`）AUX 在 epoch 中途被杀后恢复，会给部分样本**额外**训练权重

**ID**：`EML-P2-AUX-PARTIAL-EPOCH-RESUME-WEIGHTING`（复核同批报告，**机制确认**）

- `:154-155` 载荷**不含** batch cursor / sampler state / batch offset / 已消费样本计数 / `opt.step()` 次数
- `:147-150` 恢复时 `start_epoch=int(ck.get('epoch',0))` → `:158 for epoch in range(start_epoch,…)` → `:162` **重跑整个 epoch 的完整 DataLoader**
- 子 agent C 用无训练 CPU 复现件实测：32 样本 / batch 8 / 第 2 个 batch 后中断 → **16 个样本在一个逻辑 epoch 内被更新两次**；且恢复会**重新抽 permutation**（`train_generator_state` 在**创建** permutation 时前进，对已建 iterator 的 `set_state` 是 no-op），故**重放顺序不同** ⇒ 有效样本权重确实改变。

**修复（epoch-boundary rollback）**：每个 epoch 开始前保留上一**完整** epoch checkpoint；中途 deadline 只标 interruption，**不以部分 epoch 为继续起点**；下次从最后完整 epoch 重跑。
