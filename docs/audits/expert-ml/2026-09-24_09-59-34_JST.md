## 1. 这次真正复核到的“为什么五分钟就下班”

当前 `src/ml/research_h504/run.py --stage all` 仍是有限、硬编码路径，而不是 v5 所描述的持续工作图：

- 有 candidate manifest 时，H504 主线只真正机器化了 **T0 HGB 1 fit**；
- AUX 只有 `base/plus_research × seeds`，受 `max_aux_fits` 限制；
- **T1-T5、H504 MLP、H504 TCN、六项消融、第二开发块、误差驱动配对重训并不是可领取任务节点**；
- 已存在同 signature 时直接生成 `REUSED_COMPLETE`，没有新增 fit；
- 最后只要没有 wall interruption，就可以 `finalize(... stop_reason='QUEUE_DRAINED_OR_BLOCKED')` 后 `return 0`；
- `ResearchSessionReceipt` 虽然会记录 `target_met = effective >= 10800`，但 runner 没拿它决定是否允许成功退出。

因此，prompt 写“三小时”并不会自动产生三小时工作量。当前代码允许“固定几项都复用／阻塞 → 队列看起来空 → 几分钟 rc=0”。这是**执行器能力不足**，不是 13200 秒硬超时不够长。

另外，`Registry.latest_complete(signature)` 仍只检查 `signature + status.startswith('COMPLETE')`；`evidence_type` 不参与匹配。也就是说，本轮仍确认：真实／合成来源隔离不能只靠 registry 行里的展示字段，必须进入签名或复用条件。

## 2. 新的模型诊断：现有 H10 问题具有明显 regime／阈值不稳定，不应继续把预算花在盲目增大模型

这一节只用于**研究方法诊断**。H10/+30%/High 绝不替代 H504 四倍任务。

### 2.1 HGB：pooled 16.44%，但折间平均其实 23.49%，因为 83.78% 信号挤在最差一折

`reports/ml_concentration.json` / `reports/ml_search_wide.json` 的同一 HGB 路径（`wide_hgb_2`）四折：

| fold | OOS precision | signals | 总信号占比 |
|---|---:|---:|---:|
| 1 | 14.5581% | 10,173 | 83.7767% |
| 2 | 24.7238% | 1,448 | 11.9246% |
| 3 | 21.0884% | 147 | 1.2106% |
| 4 | 33.6000% | 375 | 3.0882% |

- pooled precision = **16.4375%**；
- 四折等权平均 precision = **23.4926%**；
- 最大折信号占比 = **83.7767%**。

这不是“后来几折已经稳定 30%+”——fold3 只有 21.09%，fold4 也只有 375 signals——但它清楚说明：**同一个全局阈值／同一种候选输出量，在不同市场阶段产生了数量级不同的信号密度，最终 pooled 指标被第一折压倒。**

因此当前最值得做的不是再把 HGB 从 63 leaves 加到 127 leaves，而是把“何时应当发多少信号”也建模：市场 breadth、指数回撤与波动、全市场成交/换手状态、横截面分散度等必须作为 **t 时刻可知** 的 regime 特征，或用于训练块内拟合的 regime-conditioned calibration / rank budget。

### 2.2 RF：20.84% pooled，但四折更稳定，适合当 H504 表格模型稳健基准

`wide_rf_32` 四折 precision：

- 22.8814%
- 18.3571%
- 18.0583%
- 20.7135%

pooled precision = **20.8379%**；四折等权平均 = **20.0026%**；最差折仍约 **18.06%**，没有 HGB 那种 14.6% → 33.6% 的巨大振幅。

这说明 RF 虽然离 50% 很远，但比现有 HGB 更适合作为“**先验证候选总体是否真的富集，再看复杂模型是否增加净信息**”的稳健基准。下一次真实 H504 训练不应该只有 HGB；至少应固定候选／标签／折后同时跑 Logistic、HGB、RF、ExtraTrees。

### 2.3 “只拉阈值到 50%”仍无证据可行

`reports/ml_precision_ceiling.json` 在 H10 dense OOS 网格上：

- raw score 可用的最大 precision 约 **26.7790%**；
- rank score、最少 50 个信号条件下最高约 **32.7273%**，对应 534 signals；
- 最少 250/500 个信号时最高约 **28.6385%**。

所以当前 H10 分数本身没有“阈值再狠一点就 50%”的证据。H504 是另一任务，不能直接继承这些上限；但方法论上应把 50% 的希望放在**候选总体重新定义 + 因果 regime + hard-negative discrimination + 新信息增量**，而不是继续在旧分数上做 threshold cosmetics。

## 4. 下一次真实三小时本机研究：先做 6-fit 表格首轮，不准一上来就堆神经网络

执行器门修好后，第一波真实 H504 模型预算应是**固定同一 candidate/outcome/fold 的 6 个配对 fit**，目标不是“调出漂亮训练分数”，而是确认哪一类信息能在时间外稳定提升：

1. `T0_clean_hgb`：KDJ + 长期位置 + 最小价量基准；
2. `T0_clean_rf`：同列、同候选、同折，RF稳健基准；
3. `T1_pruned_hgb`：只加通过健康检查的 family raw，不默认塞全部 cross；
4. `T1_pruned_rf`：同上；
5. `T2_regime_hgb`：增加**仅由 t 及以前计算**的市场 regime / breadth / liquidity state；
6. `T2_regime_rf`：同上。

每个 fit 必须保存全部 dev candidate prediction，并同时报：TP、signals、precision、recall、base rate、lift、AP、Brier、log-loss、每折 precision/signals、股票与日期簇敏感性。若 T2 没有相对 T0/T1 的稳定增益，不得继续给它加更复杂的神经网络包装。

然后用这六组完整预测做一次 FP/FN 解剖：

- success / risk / timeout / no-entry / unknown；
- 价格位置、长期回撤、KDJ path；
- 流动性、上市年限、股票簇；
- market regime；
- 高置信 FP 中 `risk` 与 `timeout` 分开看。

只允许从其中一个有支持的机制产生 `ERR_MECH`，并配一个 `ERR_CONTROL` 重训。**这才是“模型研究闭环”；pytest 和 Markdown 不算。**
