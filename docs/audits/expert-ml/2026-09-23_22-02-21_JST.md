## 1.【新 P0 · 执行链】`EML-P0-REUSED-COMPLETE-QUEUE-STARVATION-001`

### 1.1 直接源码证据

`run.py` 对 H504 T0：

```python
previous = registry.latest_complete(sig)
if previous is None:
    r = run_h504_hgb(...)
    ...
else:
    results.append({
        'task_scope':'H504_JOINT',
        'status':'REUSED_COMPLETE',
        'model_id':'T0', ...
    })
```

对 AUX-TCN 也是同样逻辑：命中相同 `signature` 就追加 `REUSED_COMPLETE`，不会产生新 fit；而循环之外没有 T1、T2、T3、T4、T5、H504-MLP、H504-TCN 或消融任务的 dispatcher。

随后结束状态只看 `results` 中是否有 `COMPLETE*` **或 `REUSED_COMPLETE`**：

```python
elif any(str(r.get('status','')).startswith('COMPLETE')
         or r.get('status')=='REUSED_COMPLETE' for r in results):
    status='COMPLETED_AVAILABLE_RESEARCH_NOT_CERTIFIED'
...
receipt.finalize(
    stop_reason='QUEUE_DRAINED_OR_BLOCKED',
    result_status=status,
    ...
)
return 0
```

因此，一个“本轮新增 fit = 0、只有历史复用”的进程仍可走正常成功返回。

### 1.2 与三小时要求叠加后的失败链

当前链条实际可能是：

```text
已有 T0 / AUX 签名
  -> registry.latest_complete() 命中
  -> 全部 REUSED_COMPLETE
  -> 没有 T1—T5 / MLP / TCN / 消融任务节点
  -> QUEUE_DRAINED_OR_BLOCKED
  -> run.py rc=0
  -> agent rc=0
  -> scripts/run_fixup.py 只看 child rc，外层也成功退出
```

这不是“训练完成”，而是**任务图没有继续展开**。

`target_active_seconds=10800` 目前仍主要用于 receipt 记账；外层 launcher 也没有读取 `execution_receipt.json` 来阻止 `target_met=false` 的 rc=0 会话被当作成功。

### 1.3 为什么这比继续加 prompt 更关键

`scripts/fixup_prompt.txt` 已经明确写了：

- 目标有效工作 10800 秒；
- 有 READY / INTERRUPTED / 待分析预测就继续；
- T1—T5 与神经分支需要实现；
- 不只回复计划，不再以 Markdown 作为交付。

所以当前不是“prompt 不够长”。**prompt 已经要求继续，但 Python 执行器没有持久 work registry 和 under-target fail-closed 机制。** 再往 prompt 里加几十行不会解决五分钟退出。
