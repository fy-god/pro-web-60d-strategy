## 3. 新发现：它提议的修法**与 `min_folds` 冲突到会关掉过滤器**

这是本轮最重要的**新增**结论。被审报告 `:65-80` 提议按逐折最小值过滤。问题是：「逐折」有两种语义，而 `search.py` 的既有设计**只允许其中一种**。

`search.py:346-350` 原文：

```python
346|     # A config that completed only 2 of 5 folds cannot be rank 1 either. The
347|     # threshold is `args.folds - 1`, matching the `full_fold` definition below:
348|     # `n_folds` counts folds that produced at least one signal, and a fold with
349|     # zero signals is dropped by summarise(), so requiring an exact match would
350|     # exclude every config on a grid where any fold is thin.
```

**实测两种语义，在真实 58 行上的后果**：

```text
A: 只对【已上报】的折取最小值            存活 39 / 58   冠军 wide_rf_32（不变）
B: 对【全部请求折】取最小值、未上报补 0   存活  0 / 58   ==> 空！
```

**语义 B 为什么是自我击败的**：实测 `rows with n_folds < folds_requested = 58 / 58`——**每一行**都因为 `summarise()` 丢掉零信号折而没有上报满 5 折。于是补 0 让**每一行**的最小值都变成 0，**没有任何一行存活**。而 `:361-369` 的代码是：

```python
361|     if eligible:
362|         ok = eligible
363|     else:
367|         print(f"WARNING: no config reached {min_signals} signals across at least "
368|               f"{min_folds} folds; ranking the unfiltered list instead",
```

⇒ 空集会让 `ok` **退回未过滤清单**，即**这个守卫在真实数据上会把自己关掉，而且只打印一行 WARNING**。

**这不是我的假设，是我先按 B 实现、跑出 0/58 才发现的。** 两个子 agent 也被要求独立攻击这一点。

**判定**：语义 A 是唯一与既有 `min_folds` 设计自洽的选择。被审报告的修法**未指明语义**，照其字面实现即为 B，**后果是过滤器失效**。

### 3.1 红队补上的残余缺口：**零信号折不可见，「逐折」在缺折时是空洞的**

红队的第 5 条攻击发现了一个我**没有**单独指出的缺口，我采纳并记入：

```text
folds_requested = 5        但全网格 max(n_folds) = 4      ⇒ 没有任何一行上报 5 折
summarise() 丢弃零信号折（walkforward.py:437）
⇒ 一个"请求了但一个信号都没出"的折，在产物里【完全不可见、不可检测】
```

⇒ 所以「**逐折最小值 >= 250**」这个判据在**缺折**时是**空洞的**：一个配置可以通过「每一**已上报**折 >= 250」，而某一请求折**贡献为零**。**「across every fold」在当前产物上甚至无法被验证。**

我把它与语义 B 的失败**并列**为同一个规格问题的两面：

| 缺折该怎么算 | 后果 |
|---|---|
| 补 0（语义 B） | **0/58 存活** ⇒ 触发 `:361-369` 回退 ⇒ **过滤器自我关闭** |
| 不补、只算已上报折（语义 A） | 39/58 存活，但**零信号折被静默放过** ⇒ 判据在缺折时**空洞** |

**⇒ 这不是二选一的技术细节，而是一个必须由项目显式决定的契约问题**：**「请求了但零信号的折」在下限判据里算 FAIL 还是 PASS？** 我在 §4 的修复里选择语义 A（**不算 FAIL**），理由是它与 `:346-350` 的既有设计一致；但我**明确标注这是一个需要项目确认的假设**，而不是我替项目定下的结论。**这是本轮「任务定义变更」项的实质内容。**

**另一个由红队确认、我复核成立的细节**：纯 `min(per_fold_signals)>=250`（不加折数合取）会**错误地放进 `wide_hgb_0`**（`n_folds=1`，单折 1545）。**两个合取项缺一不可**；我的修复保留了 `n_folds >= min_folds` 这一项，因此该行被正确排除（实测存活 39 而非 40）。

## 4. 交付：已验证的修复 + 变异测试（探测力是真的）

修补把资格规则**从 `main()` 里提出来**成为一个命名函数——这本身也是一个发现：**原实现把规则写在 `main()` 内联处，任何测试都够不到**，这正是它长期存活的原因。

```python
def min_fold_signals(row: dict) -> int:
    # Smallest per-fold signal count among the folds the row REPORTS.
    pf = row.get("per_fold_signals")
    pf = list(pf) if isinstance(pf, (list, tuple)) else []
    return int(min(pf)) if pf else 0
```

资格判断改为 `min_fold_signals(r) >= min_signals`。

[B] 未修版 + 同一测试文件                  exit=2   ImportError（规则不可达 ⇒ 无法测）
[C] 正确实现 + 用真实 tracked JSON 的测试   exit=0   3 passed
[D] 变异 M1：把过滤条件改回 pooled 总计     exit=1   1 failed, 2 passed
      FAILED test_thin_fold_config_is_disqualified
      assert 'wide_logistic_37' not in ['wide_rf_32','wide_logistic_37','wide_hgb_14',...]
