## 1. 独立重算：`rsi_mean_reversion` 0/100 及其机制

### 1.1 事实（本机实测，离线只读重算）

用仓库**自身**契约与实现（`experts.contracts.ExpertCard.from_mapping` + `experts.strategies.rsi_mean_reversion.predict`）对 `data/cards_100/cards.json` 的 100 张真实卡逐张重算：

```text

cards               : 100
predicted_yes_count : 0
score min/mean/max  : 0.0354 / 0.2095 / 0.4926
headroom below thr  : 0.1874
rsi_oversold mean/max : 0.0037 / 0.1388
kdj_turn full-credit  : 24
nonpanic full-credit  : 31
threshold sweep:
   0.68 -> fires 0
   0.60 -> fires 0
   0.55 -> fires 0

MATCH archive: True
```

归档侧 `data/cards_100/scores.json` → `scores.rsi_mean_reversion`：`predicted_yes_count=0`、`predicted_yes_rate=0.0`、`tp=0`、`fp=0`、`fn=50`、`tn=50`、`positive_recall=0.0`、`yes_precision=0.0`、`accuracy=0.5`、`correct=50`、`total=100`。**重算与归档一致。**

### 1.2 归档自洽性与版本契约

- 算术自洽（对全部 36 个策略逐条核验，0 处矛盾）：`tp+fp+fn+tn == total == sample_count == 100`；`tp+fn == positive_count == 50`；`accuracy == (tp+tn)/total`。
- 三份文件 `session_id` 一致：`practice-ffa6e671f3f5749e09338d8b`；`cards.json` schema `ly.kline_practice_session.v1`、`scores.json` schema `ly.kline_expert_evaluation.v2`；`cards.json` 上溯 sha256 与归档 `card_sha256=945b4c9a…ed752` 一致。
- 独立旁证：**已提交**的 `reports/webpro_cards_100_reproduction.csv`（引入提交 `bda8f3df`）中该行为 `rsi_mean_reversion,01a00acc-…,0.68,0,0,0,,0.0,0.5,0`，与本次重算吻合。

### 1.3 机制（本轮对该报告的**加强**，不是重复）

该报告 L87 说「这个阈值化复合专家对这 100 个样本没有任何发布覆盖」，并把原因落在阈值上。本轮量化后可见**两层原因**：

1. **`rsi_oversold` 项结构性近乎失效。** `rsi_mean_reversion.py:46` 为 `_clip((45.0 − RSI14)/20.0)`。本归档 100 张卡的 RSI14 最小 42.2、中位 65.9，**只有 3/100 张 ≤45，0/100 张 ≤25**，故该项均值 0.0037、最大 0.1388，而它占 **0.30** 权重——**权重最大的一项在本归档上基本恒为 0**。
2. **阈值 0.68 偏高**，而其余四项即使满额也仅 0.70（0.25+0.20+0.15+0.10），故必须几乎每项都接近满分才可能过线。实测 `kdj_turn` 有 24 张满分、`nonpanic_volume` 有 31 张满分，仍不足以补足。

**影响**：该报告的下一步建议（转向连续分量，而不是继续调固定阈值）方向正确，但**仅调阈值无效**已在数值上被排除（0.50 仍为 0）；同时**仅修 RSI 项也未必够**，因为阈值与四项之和的余量很窄。

### 1.4 与同类策略的对比（解释为何不是「共因 bug」）

36 个策略中 **6 个**预测为 0：`accumulation_base`、`first_board_breakout`、`high_level_consensus`、`reversal_engulf`、`rsi_mean_reversion`、`turnover_weak_to_strong`；其余 30 个非零（最高 `obv_volume_price=64`、`bollinger_squeeze=62`）。共同原因是**未达各自阈值**，但 RSI 是**离群者**：其余五个的最高分与阈值差距远小于 RSI。

**判定：该报告「是研究发现、不是 P0/P1 代码 bug」的定性可接受。** 策略实现自洽（公式、权重、阈值与其自身 `FORMULA` 声明一致，`:23-27` 与 `:59`、`:65` 相符），失活源于输入分布与阈值设计，而非实现错误。

### 1.5 边界（严格）

- `cards_100` 是 `experts/evaluation.py:19-20,110-111` **硬性构造**的 100 张、50 正 50 负**练习**集（`session_id` 以 `practice-` 开头），**不是自然市场基率**。

- 归档 `scores.json` **只存汇总计数**，无 per-card raw score／component；本节连续分量为本轮离线重算所得，属**软件/机制级**证据。

## 5. 研究想法（基于本轮证据，可选）

1. **把「阈值失效」与「分项失效」分开度量。** 本轮证明 `rsi_oversold` 在本归档均值 0.0037 而权重 0.30。可引入一项**可失败**的诊断：对每个策略报告「各分项对总分越阈的边际贡献」，若某分项在 ≥95% 样本上恒为 0 而权重 >0.2，则将其标为 `STRUCTURALLY_DEAD_ON_ARCHIVE`。这比 ROC-AUC 更能定位「为什么从不触发」，也对 `06-02-02` 提出的连续分量替换给出量化依据。
2. **练习集不该用来判方向，但可用于判「有没有信号」。** 本归档是硬构造的 50/50（`evaluation.py:19-20`），故其 AUC（本轮重算约 0.58）**无市场含义**；但它足以回答「连续分量是否**完全**无排序信息」——即淘汰条件的第一关。建议把这类 100-card 练习集明确定义为 **null-information gate**：只用于「若连构造集都无排序，则停止扩该因子族」，永不用于收益/精度声明。
3. **白名单化可同时解决三个开放项。** 第 2.1 节的 `FeatureSpec` 一旦落地，可顺带把 `known_at`/`deadline` 这类时间合同列**结构性**挡在门外，也能让 `check_groups()` 的警告升级为硬失败。建议的最小实现是：`feature_columns()` 在无分组时**报错**，并给六个绕过点补断言——这是一个不依赖任何新数据、可在 `BLOCKED_DATA` 状态下独立完成的软件修复。
