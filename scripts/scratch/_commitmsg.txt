Regenerate tradeability on the resolved denominator and bind every rate it publishes

src/tradeability.py had been fixed to filter censored rows before scoring, but the
reports were never regenerated, so every published fillability figure still came
from the old emitted-count denominator. This regenerates them and re-derives the
numbers the README prints.

What moved, and why each move is correct rather than a regression:

  * overall hit rate 5.533% -> 5.613% (one-word limit 4,410 -> 4,304; gapped
    10,606 -> 10,410; unfillable 10,976 -> 10,410; no_next_bar 370 -> 0);
  * signals 646,718 -> 637,499, with signals_raw 646,718 and censored 9,219 now
    recorded so the ledger reconciles;
  * `no_next_bar` going to exactly 0 is the tell that the fix worked: a row with no
    next bar cannot have a resolved forward window, so it was always inside the
    censored set. The unfillable delta of -566 decomposes exactly as -370
    (no_next_bar) plus -196 (gapped_at_limit).

`hits` (35,783) and `tradeable_hits` (33,153) are bit-identical, which is the
strongest available evidence that only the denominator moved: a hit is a hit on the
resolved rows either way. Verified over all 35 strategies by
scripts/scratch/_verify_tradeability_regen.py, which also requires
signals == signals_raw - censored, hit_rate == hits/signals, and that no row with
censored > 0 still divides by signals_raw. My first version of that probe asserted
the reason counts were invariant and flagged 142 correct changes; the invariant it
should have asserted is that every reason count stays bounded by the new
denominator, which is what it now does.

The denominator fix also makes the three published CSVs AGREE, which they did not
before: tradeability.signals == hitrate_vs_expectancy.signals for all 35 shared
strategies (measured 35/35; they differed for 34 of 35 while the emitted count was
in use). README section 9.3's note claiming "the second count is larger" is
therefore obsolete and is rewritten with the measured identity, including the
atr_trend_follow worked example: 38,463 emitted less 663 censored = 37,800
resolved.

Three errors in my own first hand-edit of the README table were caught by
scripts/scratch/_verify_readme_92.py before commit: strict_leader_momentum_v2's
unfillable (358 -> 366, share 11.05% -> 11.30%), atr_trend_follow's unfillable
(992 -> 943, share 2.61% -> 2.49%), and the emitted/resolved identity (37,137 ->
37,800). This is why the table is now parsed out of the markdown and checked cell
by cell rather than transcribed.

One audit check had encoded the bug: "tradeability signals == raw + censored for
every shared strategy" asserted the emitted-count denominator, so it went red the
moment the denominator was corrected. It now asserts
signals == emitted - censored and separately that the two files agree on the
censored count.

New bindings, all negatively tested by scripts/scratch/_probe_new_bindings.py
(10/10 mutations caught, baseline measured on a repo copy rather than assumed):
every README 9.2 cell against the CSV, the family-wide total, the obsolete framing
string, the worked-example identity, tradeability's censored field, the wide
report's stride, and both label_pairs vintage assertions. The 9.2 row regex
initially matched 1 of 4 rows because only the first row bolds both percentages;
the row-count check caught that immediately, and bold markers are now optional.

Also regenerates RESULTS.md, which is produced by src/render_results.py from the
same CSV and now prints the corrected table.
